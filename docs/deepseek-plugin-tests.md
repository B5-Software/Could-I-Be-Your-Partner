# 第三方 DeepSeek 插件实测

2026-10-08，对三个公开仓库的五个插件入口完成来源核查与隔离测试，12 项检查全部通过。测试基线为 CIBYP `1.9.0-alpha.25` 和能力 SDK `0.2.1-alpha.1`，没有向插件提供真实模型账号、聊天记录或工作区。

## 来源与结果

| 仓库 / 入口                                                                                                                           | 固定提交                                   | 核查与实测                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [dsh-tool-git](https://github.com/lxj808624/dsh-tool-git/tree/09df9e9ad56a144d61647f465b54f84bbf90113c)                               | `09df9e9ad56a144d61647f465b54f84bbf90113c` | 审查注册入口、Git runner、参数构造与保护钩子。加载 12 个工具；在临时仓库验证 status、log、diff，amend 被拒绝且 HEAD 不变。没有调用 fetch / pull 等网络操作。   |
| [dsh-conversation-exporter](https://github.com/liuyuelintop/dsh-conversation-exporter/tree/a7375d3ab5ce07e202b0822f44db15fe8417edf1)  | `a7375d3ab5ce07e202b0822f44db15fe8417edf1` | 审查后端完整导入链。合成对话通过真实 HTTP 路由导出 Markdown，保留标题与聊天正文，过滤推理；跨来源请求被拒绝，卸载后路由返回 404。未迁移其 Harness 客户端按钮。 |
| [dsh-toolkit](https://github.com/omdsh-dev/dsh-toolkit/tree/c3319d9d3e78a18191e1381461b69e84bc547575) 的 calculator / encoding / time | `c3319d9d3e78a18191e1381461b69e84bc547575` | 只审查并加载这三个子插件，不加载完整工具集合。验证数学表达式与代码输入拒绝、Unicode Base64 往返、SHA-256、IANA 时区转换与无效日期拒绝。                        |

三类插件还放入部署后的常驻 worker，验证 ESM 模块、共享 SDK 身份、Git 与上述工具调用、导出插件加载。本机独立 Node 进程的协议测试之外，已补充下面的真实 Linux VM 端到端验证。

此次真实插件测试促成以下修复：旧版导出插件的只读 webRuntime 桥；VM 的 repoDir / workDir 映射；Schemastery `const` 等保留字导出的 ESM 生成；禁用插件启动时不再执行代码。另补上会话创建失败回滚和同步排队期间的取消回归。

## 真实 VM 验证

2026-10-08 使用已安装的完整镜像 `2026.10.01`，通过 QEMU / WHPX 启动独立覆盖磁盘；Linux `6.12.107+deb13-amd64`、Node.js `20.19.2`、2 vCPU、2 GiB 内存。没有连接或重启用户正在运行的 VM，完成后已关闭测试实例并删除临时资料与覆盖磁盘。

测试走生产 `PluginManager.callTool`、`runGuestPlugin`、SSH / SFTP 部署和常驻 RPC，不用本机进程冒充 Linux。以下 12 项全部通过：

| 范围                     | 验证                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 第三方 Git（2 项）       | 12 个定义加载，Windows 目录映射为 VM 仓库，真实 status / log / diff；amend 拒绝，主机和 VM 的 HEAD 不变。           |
| 第三方工具集（3 项）     | calculator 数学与代码输入拒绝；encoding Unicode 往返和 SHA-256；time 时区转换和无效日期拒绝。                       |
| 官方文件工具（1 项）     | VM write / read / edit，文件回同步到临时主机目录；热切换 read-only 后拒绝写入，目标文件未创建。                     |
| 官方 Bash / Jobs（1 项） | 真实 Linux 后台进程、会话环境变量和完整任务输出。                                                                   |
| 常驻与模型桥（2 项）     | 跨调用计数保留，取消已开始的工具后可继续调用；模型请求经过主机测试后端，VM 设置不含测试密钥。没有请求真实模型账号。 |
| Linux PTY（1 项）        | 多行输出、40 × 160 终端尺寸、跨会话访问拒绝、取消正在运行的 sleep 后继续输入；关闭后所属进程会话无残留。            |
| 导出插件（1 项）         | Guest HTTP 路由通过 SSH 转发导出合成会话，保留标题与正文、过滤推理；跨来源请求 403，卸载后 404。                    |
| 插件重启（1 项）         | 禁用后工具不可调用，重新启用从新状态开始，工具执行不回退宿主。                                                      |

实测发现并修复三处生产问题：工具 shim 的同名包自引用导致 native 导出缺失；终端 SDK 的懒加载 `@xterm/headless` 未进入 VM 部署包；文件提供者未声明沙箱能力，导致拒绝信息被内部 `mode` 异常覆盖。修复已加入独立回归，单元测试 475 项中 472 通过、3 项跳过、0 失败；本机第三方 12 项复测也通过。

该结果覆盖此处固定的插件与 Linux 镜像；没有把平台专用原生模块、第三方 UI 或真实模型 Provider 认证当作已验证。

## 测试隔离

- 获取源代码后人工审查，再固定完整提交。测试脚本拒绝提交不匹配或工作树有改动的副本。
- 使用项目自己的 esbuild 构建已核查入口；不执行插件 npm install、postinstall 或其他生命周期脚本。
- 子进程使用临时 HOME / APPDATA / Git 配置，环境仅传递系统运行所需变量。没有 API key、npm token 或 SSH agent；Git 仓库与对话全是测试数据。
- 本机插件宿主和 worker 使用独立临时资料目录；worker 的外部主机能力在第三方探测中明确拒绝。卸载后检查工具与路由清理。
- 真实 VM 使用只读基础镜像和一次性覆盖磁盘；测试工作区、Git 仓库、SDK 日志及模型响应均为合成数据。只有本测试启动的实例会被关闭。

这是来源审查和兼容性测试，不是恶意代码认证。可信 Node 插件仍能直接访问进程所拥有的文件系统；测试进程的临时 HOME 不构成 OS 沙箱。后续版本需要重新审查。

## 复现

把上述固定提交分别准备为 `.cache/ds-thirdparty-git`、`.cache/ds-thirdparty-export`、`.cache/ds-thirdparty-toolkit`，保持干净工作树，再运行：

```sh
npm run test:ds-thirdparty
```

脚本见 `scripts/test-ds-thirdparty.cjs`。详细机器报告和构建产物哈希写入 `.cache/ds-thirdparty-results.json`，该目录不会提交；失败时返回非零退出码，不复用上一轮报告。常规 CI 使用仓库内合约测试，不自动下载或执行生态插件。

同样的固定源码准备好后，真实 VM 复现命令为：

```sh
npm run test:ds-vm -- "<已安装的 VM 资源目录>" "2026.10.01"
```

脚本见 `tests/integration/deepseek-vm.cjs`，报告写入 `.cache/ds-vm-results.json`。它自行创建临时覆盖磁盘和资料目录，不复用默认实例；失败同样清理本次启动的 VM。此测试需要实际 QEMU 和完整镜像，不加入无虚拟化环境的常规 CI。
