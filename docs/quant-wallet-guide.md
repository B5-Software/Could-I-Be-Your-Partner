# 原生钱包与量化工作台

状态：2026-11-02 开发中，尚未发布。公开的 1.9.0 安装包不包含本文新增功能。

钱包现已使用独立 Rust 签名器，新备份为 Argon2id / XChaCha20-Poly1305 认证加密。钱包设置与 TUI 钱包菜单中的「修改密码 / 升级加密」可将旧备份重新加密；需要当前密码，并重复输入新密码。操作会锁定钱包、撤销本地自动实盘权限，原有链上授权不会因此取消。保存新密码并重新导出加密备份；它仍是 secp256k1 钱包，不是后量子钱包。技术范围与恢复兼容性见 `native/wallet-signer/README.md`。

量化工作台、钱包与 Goal 使用 GUI、TUI、WebUI 共用的后台。当前研究、仿真和链上执行属于不同路径，界面与工具分别报告状态。

### 主／子 Agent 的签名范围

钱包设置新增「Agent 签名范围」，TUI 的钱包菜单也有同一入口。可查看身份、祖先范围、固定限制和累计用量，暂停本范围及后代。恢复和核对本地阻断都要独立复核并输入 `ALLOW AGENT SCOPE`；它们不会清空计数、解锁钱包或启动交易计划。未知变更留下的本地阻断与原生暂停分别处理，不能靠关闭重开应用清除限制。

量化聊天使用原生 `runSubAgent` 委派。默认子任务只获得研究工具；需要交易时，父 Agent 必须显式委派相应量化工具，并可用 `walletScope` 缩小钱包、网络、期限、费用和累计 ETH／代币／笔数预算。每笔属于该范围的签名同时占用所有祖先及钱包／组合的预算，停止前已经产生的签名仍计数。子任务不能扩大父任务范围，也不能恢复暂停或替用户授权；模型传入的身份字段不会成为签名身份。

子任务历史与主聊天独立保存。继续消息、冷恢复和钱包换授权不会产生新的预算；同一子任务的逻辑操作 ID 也保持稳定，核对同一支付／计划不会因消息变化而变成新命令。定时拆单固定绑定创建者的范围。Agent 可用 `quant_agent_scopes` 查看当前范围、祖先或后代并暂停；分页默认 5 条，可调整 `offset`／`limit`。这些是累计签名限制，已有链上 allowance、外部持有的签名、净敞口和周期预算仍须分别处理；当前还不能原地编辑已保存范围。

## 当前已实现

- 量化入口：项目、K 线、全屏、盘口快照、实验、订单、风险、审计与研究对话；支持专业面板和沉浸式对话布局，布局按项目保存。
- 原生钱包：本地创建、导入助记词 / 私钥 / 加密密钥库、解锁、锁定与加密备份。签名在独立进程中完成，Agent 工具不接收密码、助记词或私钥。
- 签名回执在返回签名前持久化，签名字节单独加密保存；重启后可在锁定状态只读恢复交易哈希。“签名结果待核实”仍占用 nonce 和预算，可在交易详情中对账；不会自动重新签名或广播。原回执缺失、损坏或被替换时保持未知，不能靠换操作 ID 再次付款。请将钱包状态与签名回执一同备份，不能用一致性校验防止管理员回滚整份旧备份。
- Base 主网与 Base Sepolia：校验 RPC 链标识，读取余额与交易状态，执行 EIP-1559 原生币转账或合约调用；提供 Uniswap V3 原生 WETH / USDC 兑换工具。
- 默认逐笔授权。设置的钱包页可阅读警告、选择钱包 / 网络 / 有效期 / 费用限制并再次确认后，授予 Agent 自动实盘权限；可随时撤销。普通工具的自动批准不授予钱包权限。
- 原生签名器核对逐笔确认、实际地址、链、期限、费用和授权代次，计划累计费用跨重启保留；旧版没有可信累计计数的权限需人工续授。锁定、换解锁会话或重启后，旧的逐笔确认不可继续签名。
- 自动授权可设置单笔 / 累计签名 ETH、累计费用预留、签名笔数、最外层目标地址 / 方法白名单和调用数据开关。GUI / WebUI 的范围表单与 TUI 的命名选项菜单使用同一后端；二次确认会冻结配置。0 / 空名单表示不限，签名后即占预算。ETH 仅限制交易 value，不限制代币或合约内部支出；最外层白名单也不检查内部收款人或合约行为。
- 「代币范围与签名额度」可添加 Base / Sepolia 的 USDC、WETH 预设或自定义合约，填写精度、单次 / 累计额度、单次授权上限及接收方 / 授权合约名单。添加规则后，自动执行只接受已配置代币的标准 ERC-20 转账、授权及支持的官方 Router02 兑换；嵌套批量、未知方法、空调用数据和原生币包装等未覆盖操作会被拒绝。空数据也可能触发 fallback，不能据此认定没有合约逻辑。
- 授权金额与转出 / 兑换输入分别累计，合计占用代币签名预算。例如授权 5 USDC 后兑换 5 USDC，累计计数为 10 USDC；这不是净损失，也不是当前链上 allowance。已签名但未广播、停止或链上失败均不退还；重新读取同一签名不重复计数。旧 allowance 仍需另行撤销，外部 spender 可能继续使用它。符号与精度不是代币身份保证，请核对合约。
- 钱包卡片的「签名预算用量」和 TUI 的同名菜单可在锁定时读取原生持久化用量，分别显示 ETH、费用、笔数和代币授权 / 转出。`quant_wallets` 也返回这些计数；读取失败表示用量不可用，不表示 0。新的人工授权会开始新预算，不重置已有计划的独立费用预算。
- 「组合签名预算」可将同一网络的 1–16 个命名钱包绑定为一个共同预算。成员钱包的所有新签名，包括人工逐笔确认、不同计划和不同 Agent，都受组合限制；单钱包权限还需另外授予。累计预算不会因钱包换授权、切换计划或重启而重置。一个钱包 / 地址在一个网络只能属于一个未解除组合，换别名不能逃避绑定。
- 组合支持暂停、人工二次确认恢复 / 解除、分页历史和共同用量。范围目前固定；调整成员或预算须人工解除并新建，旧历史保留，新建预算重新计数。创建、恢复、解除及本地阻断恢复使用独立的 `ALLOW PORTFOLIO` 二次确认，不会解锁钱包或自动启动计划。暂停不撤回已有广播、外部保存的签名或 allowance。
- 组合变更先持久保存本地阻断并中止成员的新派发；原生未确认或写入失败时，阻断跨重启保留。人工「核对并恢复本地阻断」只清理本地阻断，不能解除原生组合中的暂停、到期或预算限制。若写盘本身失败，界面会报错，不宣称已持久保存。损坏的阻断记录关闭钱包执行能力。
- 误选已绑定钱包等明确被签名器拒绝的新建配置不会生效，只撤销该次尝试的临时阻断；不会借此清除更早未确认变更留下的阻断。暂停 / 恢复的状态冲突仍需刷新核对。
- `quant_portfolios` 提供分页查询、范围 / 用量读取和暂停；不提供创建、恢复、解除或阻断恢复。组合签名预算不是净敞口、当前链上授权、投资组合估值或损失上限；这些风控能力仍待实现。
- 已签名但被停止广播的 nonce 继续占用；默认需在专用警告中明确确认原交易哈希。也可在新授权时单独开启自动替换，仍须引用当前原签名哈希并服从预算 / 停止锁 / 计划权限。当前覆盖已知未广播的签名，不是完整的待确认交易加速 API。
- Agent 可执行“检查数据 → 回测 → 检查风险 → 仿真或已获授权的实盘 → 查询结果”的工具流程。正常文字回复不会结束尚未完成的 Goal。
- 研究数据、参数、实验结果、仿真订单、实盘意图和审计持久化；研究数据带来源与哈希。研究对话独立保存在量化项目下。
- 自定义合约的只读调用、无广播模拟、ABI 编码及持久化调用 ID；大结果支持偏移量和可控长度。工具不把用户提供的 ABI 标签当作经过验证的合约身份。
- TUI 的 `/wallet`、`/quant` 现在使用项目、钱包和动作菜单，支持密码遮挡、独立授权、分页记录、本地数据文件选择，以及同一后台的研究会话。
- 实盘逻辑操作 ID 跨模型工具调用、会话恢复保持稳定；提交结果未知时先对账，不以换一个调用 ID 为理由再次付款。授权记录和合约调用原文可分页检查。
- 原生执行基础服务已作为独立 Rust 进程接入共享后台，通过认证和版本协商的私有管道通信。GUI / WebUI 共用的项目设置和 TUI 量化菜单可查看连接状态及启停；所有项目共享一个原生进程。

## 开始使用

1. 打开侧栏的量化工作台，创建项目，选择 Base 或公开交易所行情。也可导入 CSV / JSON 历史数据。
2. 运行研究模板，查看成交假设、费用、滑点、权益与回撤。导入的数据不会被标记为已经验证的交易所数据。
3. 默认使用研究对话的 Agent · Goal，清楚说明目标和预期交付物。普通对话可关闭该开关。
4. 如需实盘，在设置的钱包页创建或导入钱包并解锁。默认在每笔交易的授权卡片中检查地址、金额、费用与调用信息。自动实盘授权必须由用户在钱包页手动完成。
5. 查询链上交易状态。提交、打包、安全确认、最终确认和回滚不是同一状态；不把广播成功当作兑换完成。

Base 兑换工具当前使用 WETH，不会把原生 ETH 与 WETH 混为一谈，也不自动执行隐含的包装或跨链操作。池费率可配置；自动发现与手填地址均校验官方 Factory 的部署来源。先验证报价及最低可得数量再申请精确代币授权，授权入块后重新报价。RPC 可使用自建节点；公共 RPC 仍然有运营方依赖。

## 新闻研究与决策建议

研究 Agent 现在可以通过 `quant_news_search` 使用已配置的搜索引擎，通过 `quant_news_fetch` 阅读公开 HTTPS 来源。请求在主机执行，复用应用网络 / 代理配置，不启动 VM 或浏览器，也不携带钱包凭据。默认检索返回少量摘要，正文按需分页；`maxChars=0` 可读取网络大小上限内的完整内容。引擎选择、自己的 Provider 和 Key 沿用现有网络研究设置。

当前分析可调用 `quant_inspect(refresh=true)` 请求更新行情；`asOfUTC` 只是检查时钟，不能代替报价的观察时间、事件时间和质量检查。新闻、K 线或 AMM 采样也不能代替实盘工具的重新报价与模拟。

提示词引导它优先核验公告、治理、交易所状态、官方经济发布等一手资料，区别发布时间 / 事件时间 / 检索时间，以及事实 / 推断 / 假设。建议应说明消息的影响机制、是否可能已被定价、反证、情景条件、仓位约束、失效条件和成本；不能把转载数量当成独立验证，不能编造收益、概率或已经部署的持续任务。明确且具备条件的已授权实盘操作不以反复搜新闻或模拟为额外门槛。

成功的搜索与实际读到的网页片段会单独保存为带 SHA-256 的研究证据。GUI / WebUI 的「研究证据」页和 TUI `/quant` 项目菜单均可查看。归档不随网页缓存过期；正文片段不会被标记成全文。Agent 可以用 `quant_history(kind=research)` 找到证据 ID，再读取原先的片段。页面自报日期不等于已证实日期；无日期时显示未知。

新闻是待核实数据，不能授予签名 / 支付权限或扩大交易范围。外部服务故障与「没有相关新闻」不同：例如 HTTP 429 会显示搜索限流，不会被当成否定证据，也不盲目重试。网页读取会拒绝本机地址、IP 字面量、含凭据 URL、非标准端口及降级重定向；这不是对任意 DNS 重绑定的防火墙保证。

研究流程参考 [CFTC 关于 AI 交易机器人的提示](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/AITradingBots.html)及 [Investor.gov 关于核验社交媒体来源的提示](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-alerts/social-media-and-investment-fraud-investor-alert)。工具链、来源保护、分页、重启与 GUI 交互已验收；这不证明所有真实模型都能给出高质量市场判断，后续需按[研究评估清单](quant-research-evals.md)持续验证。

## Goal

Chat / Code 可输入 `/goal <目标>`，或使用 `/goal status`、`/goal pause`、`/goal resume`、`/goal clear`。Agent 只有调用完成工具并提供完成说明后，才将目标标为完成。用户停止、额度用尽、错误或轮数限制会中止继续执行，不会伪装成完成。

恢复旧会话时，未完成 Goal 会恢复为暂停，避免重新打开历史就执行交易。Goal 不能替代钱包授权。

## 数据和执行边界

- 当前回测是现货、只做多的 K 线研究模型：上一根收盘产生信号，下一根开盘执行，计入费用与滑点。没有盘口队列、市场冲击或高频成交精度。
- 研究账户的采样仿真订单采用完整成交假设；下述原生仿真账户另有连续队列与部分成交模型。重启后均不补造离线成交。
- Base 行情是链上池价格采样，没有真实成交量；导入 OHLC 与交易所行情分别标记。
- Rust 原生库已有 18 位金额、带序列和时效检查的 L2 盘口、独占持久日志、共享资金预留、部分成交与手续费累计舍入；进程接口可提交和撤销独立仿真意图。成交接口不向前端或 Agent 开放；当前前端研究账户仍使用上述完整成交假设，没有因此获得原生撮合能力。
- 原生进程的盘口撮合服务仍为 **仿真**：保守的同价 maker 队列支持延迟、去重、部分成交和一事件多成交的原子落盘。Coinbase 公共连续行情、原生账户、独立被动做市 PAPER / SHADOW、固定版本事件回放与三端操作已接入共享后台。Base 串行实盘拆单通过独立发件箱连接 WalletService，并使用原生签名器；它不把仿真撮合变成交易所实盘。更多策略、真实 HFT 延迟指标、中心化交易所实盘连接、跨链执行、硬件钱包及其他链签名器仍未完成。不能把 Base 现有支持称为“任意链全部兼容”。

## 原生仿真账户与订单

GUI / WebUI 在量化工作台选择项目后点击「原生仿真账户」；TUI 入口为 `/quant` → 项目 → 原生仿真账户。连接内核与行情，创建带名称、初始虚拟资产和明确风险上限的账户，或选择已有共享账户。账户默认暂停，启用后才能提交 Post-only 限价单。500 毫秒延迟和保守队列只是仿真假设。

资金、预留、订单、每一笔部分成交及本笔费用由同一原生账本管理。账户可供多个项目共享，账户暂停影响其全部策略；订单和成交历史按项目过滤，切换账户不会隐藏旧记录。暂停 / 断线 / 重启留下的挂单保持预留并标为挂起，恢复不会重新排队；先撤销旧挂单，再按需创建新意图。

共享后台在发出新单前持久保存待核对记录。确认丢失会保留记录并阻止该项目换标识再发新单。恢复健康账本后，「核对上次提交」只查询：已记录则返回原单，确实不存在则解除待核对状态，不自动补单或恢复交易。原生账户创建也按初始定义去重，不会在重试时重置已经变化的余额。两份存储不是一个跨进程原子事务，核对流程负责衔接其失败窗口。

Agent 的 `quant_native_paper` 工具走同一后台和项目范围；逻辑操作 ID 跨工具重试及研究会话恢复保持一致。此工具可管理账户、行情和仿真限价单，不能注入成交、取得密钥或绕过实盘钱包权限。

## 独立策略

GUI / WebUI 工作台选择「原生策略」，TUI 选择项目中的同名入口；Agent 使用 `quant_strategy`。先建立原生账户与行情，再定义被动做市参数、库存范围、累计成交额 / 费用 / 决策上限。PAPER 提交仿真订单；SHADOW 只记录信号，不创建订单或成交。原生进程独立评估，不逐 tick 调用 LLM。

修改参数创建新的不可变版本，已有运行固定原版本。停止只影响该次运行的委托；行情失效和重启暂停，挂起订单继续占用预留，不自动重建队列。历史保存决策、委托结果及逐笔成交；其他策略与独立实盘桥接仍待完成，也不证明 HFT 性能或盈利。仿真撤单未模拟网络延迟。

## 原生账户紧急停止

原生仿真账户面板和 TUI 的同名账户菜单提供「紧急停止并撤单」。它影响共享这个账户的所有项目：取消剩余挂单、释放订单预留、停止 PAPER / SHADOW 部署，并用单条原生账本事件持久保存停止锁。已成交数量、费用、余额和历史保留，其他账户继续按原状态运行。

停止请求直接进入控制通道，不等待宿主普通下单队列。原生端仍按顺序处理命令和成交；停止前已经发生的成交不会被回滚。存储故障时明确返回失败或未知结果，并保持执行暂停，不谎报已撤单或释放资金。

Agent 可用 quant_native_paper 的 halt 动作停止所绑定账户，必须保留同一次请求的 operationId；它没有解除锁定的工具权限。GUI / WebUI / TUI 解除操作需要明确确认，并核对当前账户和停止锁标识；账户或锁变化后旧确认失效。解除后账户仍暂停，已撤订单和已停止策略不会自动恢复。

此控制针对原生仿真账户；实盘钱包的锁定和自动授权仍由钱包服务独立管理。它不表示已经具备所有交易场所的实盘批量撤单或全产品应急停机。

## 行情记录与事件回放

GUI / WebUI 的项目工具栏选择「行情记录与事件回放」，TUI 在项目菜单进入同名页面；Agent 使用 quant_event_data 工具。先连接公共行情，录制时从该连接的串行队列取得一致的有界快照，再保存规范化盘口、成交与失效输入。不会重启行情或改变当前订单。

结束录制后刷盘，保存文件与元数据 SHA-256；失败或中断的记录不能直接运行回放。当前单条最多 256 MiB、24 小时，同时最多四条；超额或写入背压明确失败，不悄悄丢数据。尚无自动归档、压缩或配额清理；长期运行前需检查磁盘空间。

选择一条完整记录、策略及版本号，后台固定其版本链、市场规则、当前引擎二进制摘要、风险和初始虚拟资金。默认复制所选原生仿真账户的**可用**余额；工具也可明确提供实验初始资金。回放使用独立进程与账本，不扣原账户余额，不持有实盘凭据或连接交易场所；同一后台同时运行一个回放实验。

虚拟时钟复用现有原生策略、资金预留与 FIFO 撮合，按 50ms 调度推进；没有行情的时间段也推进时钟并执行过期暂停。完成后撤销该实验的仿真挂单，保存决策、订单、每笔成交、费用、拒绝事件和账本摘要。界面 / 工具可取消、查看进度、读取分页历史；Agent 状态查询支持最多 30 秒等待，避免连续空查询。

「交易贡献」是相对实验初始资产数量的增量，按末次有效盘口中价估值，已计入仿真成交费用；它不等于已实现利润。末尾没有有效报价时不计算该估值。原有库存本身的价格涨跌不被当作策略交易贡献。

这是**主机适配器输入时间**上的历史实验，不是实盘命令 / 回报时间的精确复演；也没有全部原始交易所数据、L3、市场冲击或撤单网络延迟。500ms 到达、同价 L2 FIFO 和立即仿真撤单仍是明确的模型假设，不是 HFT 成交精度或收益保证。原生分发已接入六平台构建，本地已验证 Windows x64 实际安装资源；其他平台仍待原生 CI 验收，尚未发布这些新功能。

## 原生连续行情

在量化项目设置中先连接原生进程，再选择「公开连续行情」中的交易对和模拟 Maker 费率，连接后可查看连续盘口。GUI 与 WebUI 使用同一界面；TUI 入口为 `/quant` → 原生执行进程 → 公开连续行情。当前支持 ETH-USD、BTC-USD、SOL-USD；这是交易所公共现货数据，不是 Base AMM 的可执行报价，也不会创建账户或开启真实交易。

连接器订阅 [Coinbase 官方公开频道](https://docs.cdp.coinbase.com/coinbase-app/advanced-trade-apis/websocket/websocket-endpoints)，核对整条连接的消息序列，再分别生成内核盘口与成交序列。它使用价位的绝对数量，并区分成交的 maker 方向；初始历史成交快照不会用来撮合。只有盘口、成交与心跳初始化完成并追平当前数据后，盘口才可执行。丢失消息、无效数据、积压或网络政策变更会失效当前盘口；恢复快照不会自动重建或重新激活旧委托队列。

大型初始快照可能落后于实时流，因此先完整追平，不把接收时间冒充行情发生时间。原生盘口只保存明确覆盖范围内的价位，范围外不假定为空队列。延迟数据和心跳失效不能继续下单；暂停或断线后原生未完成意图保持挂起及资金预留，需要后续显式处理。

连接器通过公开的交易所时间接口估算时钟差异及请求往返误差，保守地把事件投影到主机时钟，不修改系统时间。内部 `sourceTimeNs` / 成交 `time_ns` 是保守映射时间；`providerTimeNs` / `provider_time_ns` 保留原始交易所纳秒时间，`sourceClock` / `source_clock` 记录映射、误差范围及校准时刻。内核校验映射一致性和校准时效；本机时钟跳变会停止当前流。这是带假设的纸面撮合模型，不是经过认证的时钟或 HFT 性能保证。

HTTP 和 WebSocket 均在主机使用应用的网络 / 隐私配置。每条流拥有自己的传输实例，网络设置变化会立即断开旧连接；隐私通道未连接时不回退直连。停止原生进程会停止全部数据源，进程故障不自动重启交易或重复金融命令。三端共享连接状态，不因多开前端创建多份原生进程。

各交易对共用一个有界订阅队列，发送间隔至少 250 毫秒，避免多端同时连接或重连时集中发送订阅。状态保留连接尝试次数、延迟挂起次数及实际处理成交数；迟到行情恢复可读不代表旧的挂起订单已经恢复执行。
- 本机用户自己的任意脚本或 Shell 与程序拥有同级系统权限，应用内策略不是抵御同一系统用户恶意代码的操作系统隔离边界。

## 发布包检查

`npm run check:runtime-deps` 使用打包器实际收集的生产依赖，检查普通依赖和必需 peer 依赖，并隔离加载 DSH、插件宿主和 Claude SDK。打包后再次检查最终归档，并用安装包自带 Node 启动真实后台。检查禁止借用开发仓库中的模块。

本轮修复了必需 DSH 组件仅在开发环境可用、发布包缺少 `dsh-session-title` 等模块的问题。必须以新构建的安装包验证结果为准；已有下载文件不会因修改源码自动修复。

原生量化运行时固定 Rust 工具链和六个目标，在各平台 CI 主机编译。Windows 静态链接 CRT，Linux 使用 musl 静态可执行文件，macOS 在压缩前签名。程序以压缩资源和清单随应用分发，首次启动前核对压缩包与原始程序的 SHA-256、大小、协议及实际架构，再写入用户私有的按内容哈希隔离的缓存；运行时不需要 Rust 或在线安装依赖。

缓存版本互不覆盖；损坏缓存只从验证通过的资源修复。安装资源缺失或校验失败时明确拒绝启动，不借用开发仓库的程序。macOS 本地重新签署整个 App 不会改写压缩资源内的程序，因此不会破坏其校验哈希；这一点已有签名目标扫描测试，但不替代真实 macOS 签名 / 公证验收。旧缓存的自动清理仍待实现。

## 实盘全局停止

GUI / WebUI 在「设置 → 钱包」使用「停止所有实盘」；TUI 在 `/wallet` 菜单选择同名操作。它覆盖 CIBYP 的所有钱包和工作区：先保存独立停止记录、关闭解锁会话、阻止新签名和广播，再异步暂停原生实盘计划；停止不排队等待普通钱包操作，不暂停 PAPER 账户。正在暂停或失败会单独显示，失败可重试，不能据此声称所有链上交易已取消。

已广播或结果未知的交易保留哈希、费用和历史，停止期间仍可读取余额、核对结果和导出加密备份；已有链上代币批准不会被本地停止撤回。未广播意图取消或被代次屏障阻止，不能因为后来解除停止锁而重新发送。

解除需要先阅读说明，再输入 `RESET LIVE` 二次确认；原生暂停尚未确认时不允许解除。解除后钱包仍锁定、权限为逐笔人工确认、计划保持暂停；重新解锁、授权和启动都须单独进行。停止前的自动授权绑定旧代次：只恢复旧钱包状态文件也不能使其重新生效。此保护依赖独立停止记录仍存在；不声称能抵抗操作系统同用户任意代码或整个存储目录回滚。

停止记录使用校验和、同步写入及原子替换；记录损坏时关闭钱包执行能力。写入失败仍保持当前进程的停止屏障，但不能承诺这次停止已跨重启保存；界面提示修复存储并重试。

Agent 的 `quant_live_control` 只有 `status` / `halt`，没有解除、解锁或授予权限的动作。单个计划停止仍用 `quant_live_execution stop`；全局动作应符合用户的全局停止指令或明确风控授权。此控制不取消交易所订单、不撤回其他钱包客户端的操作，也不保证极端行情损失。

## 可复现验证

新增开发中的 Base 定时拆单桥：共享后台 execution API 和 Agent 的 quant_live_execution 工具可管理真实钱包计划。GUI / WebUI 在量化项目工具栏选择「实盘计划」，TUI 从项目菜单进入同名页面；选择命名钱包和买卖方向，填写输入金额、段数、间隔、滑点和累计预估费用预算，创建后默认暂停。仅在用户已手动授予自动实盘范围且钱包已解锁时才能另行启动，创建计划本身不授权或签名。面板可查看最终确认进度、费用预留、执行记录与哈希，支持停止和只读对账。关闭面板不停止后台执行。当前按每段最终确认后的间隔串行执行；累计费用为保守预估预算，已有批准、已广播交易和真实链上费用不能靠本地停止撤回。范围与验收见实现进度。

- `npm run test:quant:chain`：下载固定版本、校验 SHA-256 的官方 Anvil；在隔离的本机 EVM 中运行真实签名器、原生币转账、合约模拟 / 执行、Agent 重复调用和重启对账。不连接真实资产，不消耗模型额度。
- `npm run test:quant:execution`：构建真实原生进程，在隔离 Anvil 上运行原生调度、加密签名、测试代币批准 / 转移、最终确认、费用预算、签名中停止 / 撤权 / 暂停 / 配置变更及隐藏确认后的重启恢复。合约为固定价格测试夹具；运行时校验源码和字节码摘要。打包验证可在 build:node-core 后执行 node scripts/test-quant-chain.cjs --execution --bundled；不依赖 Solidity 编译器、外部模型或真实资金。
- `npm run test:quant:bundle`：对打包后的 Node 后台重复运行同一流程，覆盖独立的 Rust 签名器。模型响应由本机 HTTP 测试服务器提供，实际经过生产网络初始化；不靠替换全局 fetch 绕过初始化。
- `npm run test:quant:native`：使用本机 Rust 工具链构建原生进程，再验证真实子进程认证、版本协商、单写入锁、共享后台、订单持久性、丢失确认恢复和停机。显式开发覆盖可使用 `CIBYP_QUANT_ENGINE_BIN`，不是 Agent 可修改的设置。
- `npm run prepare:quant-engine`：构建并验证当前平台的压缩原生资源，编译前需要固定的 Rust 工具链和目标；CI 自动准备。`node tests/integration/quant-native-resource.cjs` 使用该真实程序验证受管资源启动、缓存修复、实时时钟保护、历史回放及进程回收，并对同一个已验证程序运行 20 项账本、资金预留、部分成交、独立策略、恢复、仿真紧急停止、实盘专用暂停、私有执行发件箱与回放集成测试。`--resources <安装资源目录>` 可检查实际打包产物；所有账户和订单均在隔离的虚拟环境，不操作真实资产。
- `npm run test:quant:native:bundle`：通过打包后的 Node 后台验证同一原生进程、账户绑定持久化、一致的账户 / 历史视图、重启暂停与进程回收；不发送网络请求或真实订单。
- `electron tests/integration/quant-workbench.cjs`：共享后台与真实 Electron 界面的隔离验收；行情及模型为明确标记的测试数据，截图不代表实盘收益。
- `cargo test --manifest-path native/quant-engine/Cargo.toml --locked`：原生库精度、盘口恢复、日志完整性及订单账本验收。另运行 `cargo fmt --check` 和 `cargo clippy --all-targets --locked -- -D warnings`（加相同 manifest-path）。

这些检查证明各自覆盖的行为，不构成完整套件已交付或公网实盘已验收的证明。全量差距和后续验收见[实现进度](quant-implementation-status.md)。

原生确认写入失败时，记录也可能在重启重放后出现，因此按“结果未知”处理，不自动重发；账本暂停后先检查存储并恢复。重启保持暂停并保留预留资金，成交状态不能由聊天或界面伪造。进程没有网络连接、密钥或真实资金权限。Unix 新建目录 / 文件使用私有权限，日志和锁文件拒绝符号链接；Unix 权限验收在 Linux CI 运行，Windows 本地不能证明该项通过。
