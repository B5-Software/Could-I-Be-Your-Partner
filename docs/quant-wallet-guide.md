# 原生钱包与量化工作台

状态：2026-11-11 开发中，尚未发布。公开的 1.9.0 安装包不包含本文新增功能。

钱包现已使用独立 Rust 签名器，新备份为 Argon2id / XChaCha20-Poly1305 认证加密。钱包设置与 TUI 钱包菜单中的「修改密码 / 升级加密」可将旧备份重新加密；需要当前密码，并重复输入新密码。操作会锁定钱包、撤销本地自动实盘权限，原有链上授权不会因此取消。保存新密码并重新导出加密备份；它仍是 secp256k1 钱包，不是后量子钱包。技术范围与恢复兼容性见 `native/wallet-signer/README.md`。

量化工作台、钱包与 Goal 使用 GUI、TUI、WebUI 共用的后台。当前研究、仿真和链上执行属于不同路径，界面与工具分别报告状态。

### 主／子 Agent 的签名范围

钱包设置新增「Agent 签名范围」，TUI 的钱包菜单也有同一入口。可查看身份、祖先范围、固定限制和累计用量，暂停本范围及后代。恢复和核对本地阻断都要独立复核并输入 `ALLOW AGENT SCOPE`；它们不会清空计数、解锁钱包或启动交易计划。未知变更留下的本地阻断与原生暂停分别处理，不能靠关闭重开应用清除限制。

量化聊天使用原生 `runSubAgent` 委派。默认子任务只获得研究工具；需要交易时，父 Agent 必须显式委派相应量化工具，并可用 `walletScope` 缩小钱包、网络、期限、费用和累计 ETH／代币／笔数预算。每笔属于该范围的签名同时占用所有祖先及钱包／组合的预算，停止前已经产生的签名仍计数。子任务不能扩大父任务范围，也不能恢复暂停或替用户授权；模型传入的身份字段不会成为签名身份。

子任务历史与主聊天独立保存。继续消息、冷恢复和钱包换授权不会产生新的预算；同一子任务的逻辑操作 ID 也保持稳定，核对同一支付／计划不会因消息变化而变成新命令。定时拆单固定绑定创建者的范围。Agent 可用 `quant_agent_scopes` 查看当前范围、祖先或后代并暂停；分页默认 5 条，可调整 `offset`／`limit`。这些是累计签名限制，已有链上 allowance、外部持有的签名、净敞口和周期预算仍须分别处理；当前还不能原地编辑已保存范围。

## 当前已实现

- 量化入口：项目、K 线、全屏、盘口快照、实验、订单、风险、审计与研究对话；支持专业面板和沉浸式对话布局，布局按项目保存。
- 原生钱包：本地创建、导入助记词 / 私钥 / 加密密钥库、解锁、锁定与加密备份。签名在独立进程中完成，Agent 工具不接收密码、助记词或私钥。
- 签名回执在返回签名前持久化，签名字节单独加密保存；重启后可在锁定状态只读恢复交易哈希。“签名结果待核实”仍占用 nonce 和预算，可在交易详情中对账；不会自动重新签名或广播。原回执缺失、损坏或被替换时保持未知，不能靠换操作 ID 再次付款。请将钱包状态与签名回执一同备份，不能用一致性校验防止管理员回滚整份旧备份。
- Base 主网与 Base Sepolia：校验 RPC 链标识，读取余额与交易状态，执行 EIP-1559 原生币转账或合约调用；提供 Uniswap V3 原生 WETH / USDC 兑换工具。新增共享自定义 EVM 网络配置和逐笔 type-2 签名，具体范围见下文。
- 默认逐笔授权。设置的钱包页可阅读警告、选择钱包 / 网络 / 有效期 / 费用限制并再次确认后，授予 Agent 自动实盘权限；可随时撤销。普通工具的自动批准不授予钱包权限。
- 原生签名器核对逐笔确认、实际地址、链、期限、费用和授权代次，计划累计费用跨重启保留；旧版没有可信累计计数的权限需人工续授。锁定、换解锁会话或重启后，旧的逐笔确认不可继续签名。
- 自动授权可设置单笔 / 累计签名 ETH、累计费用预留、签名笔数、最外层目标地址 / 方法白名单和调用数据开关。GUI / WebUI 的范围表单与 TUI 的命名选项菜单使用同一后端；二次确认会冻结配置。0 / 空名单表示不限，签名后即占预算。ETH 仅限制交易 value，不限制代币或合约内部支出；最外层白名单也不检查内部收款人或合约行为。
- 「代币范围与签名额度」可添加 Base / Sepolia 的 USDC、WETH 预设或自定义合约，填写精度、单次 / 累计额度、单次授权上限及接收方 / 授权合约名单。添加规则后，自动执行只接受已配置代币的标准 ERC-20 转账、授权及支持的官方 Router02 兑换；嵌套批量、未知方法、空调用数据和原生币包装等未覆盖操作会被拒绝。空数据也可能触发 fallback，不能据此认定没有合约逻辑。
- 授权金额与转出 / 兑换输入分别累计，合计占用代币签名预算。例如授权 5 USDC 后兑换 5 USDC，累计计数为 10 USDC；这不是净损失，也不是当前链上 allowance。已签名但未广播、停止或链上失败均不退还；重新读取同一签名不重复计数。旧 allowance 仍需另行撤销，外部 spender 可能继续使用它。符号与精度不是代币身份保证，请核对合约。
- 钱包卡片的「签名预算用量」和 TUI 的同名菜单可在锁定时读取原生持久化用量，分别显示原生币、费用、笔数和代币授权 / 转出。`quant_wallets` 也返回这些计数；读取失败表示用量不可用，不表示 0。新的人工授权会开始新预算，不重置已有计划的独立费用预算。
- 「组合签名预算」可将同一网络的 1–16 个命名钱包绑定为一个共同预算。成员钱包的所有新签名，包括人工逐笔确认、不同计划和不同 Agent，都受组合限制；单钱包权限还需另外授予。累计预算不会因钱包换授权、切换计划或重启而重置。一个钱包 / 地址在一个网络只能属于一个未解除组合，换别名不能逃避绑定。
- 组合支持暂停、人工二次确认恢复 / 解除、分页历史和共同用量。可人工编辑名称、期限、费用及既有资产的累计 / 周期预算，保留原计数与修订历史；成员和资产身份保持固定。创建、编辑、恢复、解除及本地阻断恢复使用独立的 `ALLOW PORTFOLIO` 二次确认，不会解锁钱包或自动启动计划。暂停不撤回已有广播、外部保存的签名或 allowance。
- 组合变更先持久保存本地阻断并中止成员的新派发；原生未确认或写入失败时，阻断跨重启保留。人工「核对并恢复本地阻断」只清理本地阻断，不能解除原生组合中的暂停、到期或预算限制。若写盘本身失败，界面会报错，不宣称已持久保存。损坏的阻断记录关闭钱包执行能力。
- 误选已绑定钱包等明确被签名器拒绝的新建配置不会生效，只撤销该次尝试的临时阻断；不会借此清除更早未确认变更留下的阻断。暂停 / 恢复的状态冲突仍需刷新核对。
- `quant_portfolios` 提供分页查询、范围 / 用量 / 持仓、Base 权益下限复核和暂停。配置、恢复和解除走人工复核。组合签名预算与链上授权、持仓估值和权益下限分别计算。
- 已签名但被停止广播的 nonce 继续占用；默认需在专用警告中明确确认原交易哈希。也可在新授权时单独开启自动替换，仍须引用当前原签名哈希并服从预算 / 停止锁 / 计划权限。当前覆盖已知未广播的签名，不是完整的待确认交易加速 API。
- Agent 可执行“检查数据 → 回测 → 检查风险 → 仿真或已获授权的实盘 → 查询结果”的工具流程。正常文字回复不会结束尚未完成的 Goal。
- 研究数据、参数、实验结果、仿真订单、实盘意图和审计持久化；研究数据带来源与哈希。研究对话独立保存在量化项目下。
- 自定义合约的只读调用、无广播模拟、ABI 编码及持久化调用 ID；大结果支持偏移量和可控长度。工具不把用户提供的 ABI 标签当作经过验证的合约身份。
- TUI 的 `/wallet`、`/quant` 现在使用项目、钱包和动作菜单，支持密码遮挡、独立授权、分页记录、本地数据文件选择，以及同一后台的研究会话。
- 实盘逻辑操作 ID 跨模型工具调用、会话恢复保持稳定；提交结果未知时先对账，不以换一个调用 ID 为理由再次付款。授权记录和合约调用原文可分页检查。
- 原生执行基础服务已作为独立 Rust 进程接入共享后台，通过认证和版本协商的私有管道通信。GUI / WebUI 共用的项目设置和 TUI 量化菜单可查看连接状态及启停；所有项目共享一个原生进程。

## 滚动样本外验证

在 GUI / WebUI 的实验区或 TUI `/quant` 项目菜单中打开「滚动样本外验证」。选定 K 线数据集，填写训练和验证窗口的 K 线数、轮数、快慢周期候选、初始资金、费用、滑点和买入分配。每组最多填六个周期，快周期必须小于慢周期，至少生成两组候选。默认取最近 210 根已收盘 K 线，前 120 根用于首轮训练，之后三段各 30 根用于验证。留在窗口之前的 K 线数量会记录在报告中。未选择数据集时，后端将当前市场的已收盘 K 线固定为新快照。

每轮训练从相同的模拟现金开始，按期末权益、最大回撤、快周期和慢周期依次排名。选定参数后用训练尾部收盘价预热，最早在样本外第一根开盘成交。下一轮训练可以包含之前已结束的验证区间。样本外区间彼此不重叠，现金和持仓跨轮延续。总体收益、成交、费用和权益曲线只统计样本外交易，持仓按期末收盘价估值。窗口按实际观察到的 K 线计数，空档不会补成虚构 K 线。

保存的报告包括数据集、各轮区间、所选周期和可展开的训练排名。TUI 可从「回测实验」重新打开报告。Agent 用 `quant_walk_forward` 的 `run` 保存实验，再用 `fold` 按轮读取训练证据。若根据同一批验证结果反复改候选，应另外保留以后才取得的数据做独立验证。实验按下一根开盘与固定滑点模拟，盘口排队、延迟和市场冲击仍须使用对应的执行模型验证。

## Base 链上成交历史

在 GUI / WebUI 的量化图表或 TUI `/quant` 项目菜单中打开「链上成交」。选择 K 线周期和区间数后，可录制最近已最终确认的区间，或选中已保存的数据集从其结束时间接续。每次最多录制六小时。已保存的每段保留链、池、费率、时间区间、区块边界及逐笔成交，重启后仍可查看。可用图表的数据集选择器切换到任一段，查看真实成交生成的 OHLCV 或运行 K 线回测。

Agent 可用 `quant_base_history` 录制、接续或分页读取 Swap 日志。`endTime` 可指定与周期对齐的 UTC 秒，补录旧区间需要 RPC 提供归档查询。价格按池中实际交换的 USDC / WETH 计算，原子单位保留精确的 WETH 和 USDC 成交量。单边为零的日志保留在原始记录中，无有效成交的区间不生成 K 线。每段数据对应当前费率的一个池。Base 主网默认 RPC 限流时，应用会通过 PublicNode 重新读取整段公共成交。配置自定义 RPC 后仅使用该节点。K 线回测以同一数据集的下一根有成交 K 线开盘模拟执行。

「后台录制」可从最近区间或所选数据集开始。共享后端按完整的最终确认区间分段写入，默认每段约 15 分钟，长周期至少包含一根 K 线。无成交的区间也保存检查点。关闭对话或前端不影响正在运行的共享后端。启用量化的后端重启后从最近检查点补录。网络暂时不可用时延后重试，节点拒绝过大的范围时可自动缩小分段。修改行情配置、归档丢失或区块锚点不一致时暂停并保留已保存的数据。「查看最近归档」切换图表到该段。Agent 使用 `record_start`、`record_status`、`record_stop` 操作，暂停后可用 `record_start` 加 `resume: true` 继续。

选中原始归档后，在「链上成交」中使用「生成回测数据集」，默认回溯一天。系统沿检查点连接同链、同池、同费率、同周期的归档，校验各段哈希与衔接区块，生成固定数据集并切换图表。图表标出内部无成交区间，并显示实际归档范围是否短于请求。Agent 可用 `quant_base_history` 的 `series` 动作指定最后一段 `datasetId` 和 `windows`，再将返回的 ID 传给 `quant_backtest`。单次读取最多 512 段、10,000 个时间区间及 128 MiB 原始归档。实验报告保存所用归档 ID、裁切范围和缺口起止时间。SMA 按有成交的 K 线计算，模拟成交用下一根有成交的 K 线开盘，报告记录每笔模拟成交跨越的空区间数。

选中原始归档或合并数据集后，在实验区或 TUI 项目菜单打开「AMM 逐笔仿真」。支持买入持有及按 Swap 观察值更新的双均线。每个区块结束后更新策略，最早在达到配置延迟的下一个有成交区块末使用历史 QuoterV2 做精确输入报价。报告保存信号和报价的区块、报价代币数量、价格边界拒绝、跨 tick 数和期末池价格。报价已计入池手续费与价格冲击。中途估值使用观察到的 Swap 比率，期末使用历史 `slot0`。每次报价都基于原始历史池状态。报告可离线查看，重跑需要支持 EIP-1898 和归档状态的 RPC。最多 10 万个 Swap 和 32 次报价。Agent 用 `quant_amm_replay` 的 `run` 和 `attempts` 动作运行及分页检查。 [QuoterV2 源码](https://github.com/Uniswap/v3-periphery/blob/main/contracts/lens/QuoterV2.sol) · [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898)

网络成本可选每笔固定 USDC 或「按历史区块估算」。历史模式把报价 Gas 加上配置的路由开销，用历史 L2 基础费和模拟优先费计算执行成本。归档区块的 GasPriceOracle 用代表性的未签名 Router02 交易估算 L1 数据费，Isthmus 启用后同时计算运营商费。结果按同区块的 WETH/USDC 池价向上折成 USDC 最小单位。买入前预留每笔费用上限，超限的报价会记录证据并跳过，历史费用证据缺失会中止实验。报告保存区块哈希、未签名交易、各项费用及估值。估算覆盖单笔兑换，包含默认 55,000 单位路由开销和可配置优先费，审批交易等额外动作仍需单独建模。Agent 用 `feeMode: "historical"`、`networkFeeCapUsdc`、`routerOverheadGas` 和 `tipGwei` 配置。 [GasPriceOracle 源码](https://github.com/ethereum-optimism/optimism/blob/develop/packages/contracts-bedrock/src/L2/GasPriceOracle.sol) · [Base Isthmus](https://docs.base.org/upgrades/isthmus/overview)

选中同类归档后，也可在 GUI / WebUI 实验区或 TUI 项目菜单打开「AMM 多笔情景仿真」。从归档中指定一个最终确认的成交区块，留空时使用最后一个。填写虚拟 WETH 余额和最多八笔有序兑换，每笔可以设最低到账量。起始 USDC 为零，可以先卖出 WETH 再用所得 USDC 买回。每笔交易通过 Router02 在相隔两秒的模拟区块中执行，后续交易继承仿真池价格和余额。报告保留每笔到账量、对应起始区块独立报价的差值、价格和余额，并在首次回滚处停止。Agent 使用 `quant_amm_scenario` 的 `run` 和 `get`。重新运行需要支持 `eth_simulateV1` 的归档 RPC。该实验只执行给定交易，外部市场交易及流动性变化留在原历史中。报告记录兑换 Gas 单位，收益按扣除池手续费、未扣网络成本计算。 [Base RPC 文档](https://docs.base.org/base-chain/api-reference/ethereum-json-rpc-api/eth_simulateV1)

## 自定义 EVM 网络

GUI / WebUI 钱包页的「EVM 网络」及 TUI `/wallet` 的同名入口共用一份配置。可以编辑内置 Base RPC，或添加最多 16 个网络，填写名称、十进制 Chain ID、RPC URL、原生币符号及额外费用预留。当前只支持 18 位原生币精度；RPC 需使用 HTTPS，本机测试允许 HTTP 回环地址。URL 中的登录信息、查询参数和片段不受支持。

先探测 RPC 的链 ID、创世块和 EIP-1559 能力，再复核冻结的网络信息并确认保存。链 ID 与已保存的创世块不一致时拒绝使用。首次连接的数据由 RPC 自报，仍需使用可信服务商或自己的节点。列表只显示 RPC 来源域名，完整路径保存在本机配置并只在编辑界面显示；不要将它复制给 Agent。

「转出原生币」选择网络、收款地址和金额后进入逐笔审批列表，核对网络 ID、金额、费用和地址后明确批准。资产列表可追踪自定义代币。自定义 EVM 已支持单钱包、组合及主／子 Agent 签名预算；自动操作需在钱包页选择网络、复核范围并输入 `ALLOW LIVE`。保存网络本身不解锁、不授权、不启动计划。代币及周期规则可选同一自定义链，预算按 18 位原生币数量计量，跨网络直接相加，不做价格 / 法币折算。

研究 Agent 先用 `quant_wallets` 查看网络 ID / 能力，再在 `quant_base_inspect`、`quant_contract`、`quant_live_transaction` 一致传入 `chainId`；省略时保留项目 Base 网络。ABI 编码返回的 `callId` 绑定链和研究工作区，执行用同一链；重试保留 `operationId`，结果未知先对账。自动操作同时占用钱包、组合和所有祖先范围，钱包重授权不清空后两者。新增网络后需重新打开研究会话，子 Agent 只能缩小当次继承的链范围。兑换、Permit2 和价格适配仍限已接入的 Base 网络，EVM 支持不代表兼容所有应用。

通用费用按 Gas 上限计算，其他 L2 附加费用可填写原生币预留。Base 和 Base Sepolia 在签名前、广播前各从当前区块核对 L1 数据费和运营费。将两项费用加到已批准的 L2 Gas 上限后，估算超出原预留就会停在广播前。RPC 返回过期或无效的报价时也会停止。链上实际费用仍取决于入块时的费率。编辑 / 停用网络会使旧审批失效、暂停对应自动权限、阻止尚未发出的请求；钱包列出需要重新授权的链。已发送或结果未知的交易只读核对，不自动重发。恢复网络不会恢复自动权限，仍需重新复核授权。[GasPriceOracle 费用接口](https://github.com/ethereum-optimism/optimism/blob/develop/packages/contracts-bedrock/src/L2/GasPriceOracle.sol)

完整运行状态备份需包含 `networks.json`、钱包状态和原生签名回执，单独导出的加密密钥备份只负责恢复密钥。丢失自定义网络记录时应用拒绝执行相关交易，不会静默重建网络身份。当前实现不包含非 EVM 或 legacy / access-list / blob 交易。隔离链转账测试不等于各公网网络或真实协议已验收。[交易格式](https://eips.ethereum.org/EIPS/eip-1559) · [网络身份与用户复核参考](https://eips.ethereum.org/EIPS/eip-3085)

## 网页应用连接

开启量化功能，并使用本机钱包后台时，主机 Playwright 浏览器和已配对的 Chromium 扩展都会提供钱包发现和请求接口。站点可通过 [EIP-6963](https://eips.ethereum.org/EIPS/eip-6963) 发现完整应用名；没有其他钱包时也提供 `window.ethereum`。请求和账户 / 链变更事件采用 [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193) 的接口形式，当前只实现下述方法子集。VM 浏览器和连接远端后台的浏览器尚未接入。

站点调用 `eth_requestAccounts` 后，在 GUI / WebUI「设置 → 钱包 → 应用连接」或 TUI `/wallet` → 应用连接，查看由主机浏览器核对的实际站点来源，选择一个命名账户和已登记网络，再复核确认。页面自报来源和子框架请求不会被信任。仅允许 HTTPS 站点，本机测试可用 HTTP 回环地址。连接有效期 24 小时，保存的公开账户 / 网络可在后台重启后继续使用；连接不会解锁钱包、授予 Agent 自动权限或产生链上授权。观察账户可连接查询，仍不能签名。

已连接站点支持账户 / 链查询、有限的公开链 RPC 读取、需人工复核的 `wallet_switchEthereumChain` 和 `eth_sendTransaction`。交易仅接受 `from`、`to`、`value`、`data`、`chainId`；费用由钱包估算并在审批卡片复核。每笔网站交易始终需要单独批准，即使这个钱包已有 Agent 自动权限。卡片显示请求来源、金额、地址、调用数据和费用，实际签名仍经原生签名器。网站请求不是研究 Agent 的工具调用，不会借用其自动授权。

同一文档中同一内部请求 ID 的重试绑定原内容，不能重复付款或替换参数。站点重新调用 `request()` 会生成新 ID，应先核对已提交结果，不能把重新发送当成同一请求重试。断开连接、到期、页面跳转或网络修订会阻止尚未广播的操作；已发给节点或结果未知的交易继续保留记录，只读对账，不自动重发。已有链上 allowance 也不会随站点断开而撤回。

站点连接记录在钱包目录的 `app-connections.json`，只保存连接和公开账户的引用。删除聊天记录不会删除交易回执。网站的交易请求使用钱包估算的费用，自定义 gas 字段和原始交易广播暂未支持。

网站可通过 `wallet_addEthereumChain` 提议添加网络。在「应用连接」中核对来源、链 ID 和币种，填入你信任的 RPC 地址。网站建议只显示来源，钱包仅请求你填入的节点。核验通过后会显示创世区块哈希、费用预留及 EIP-1559 能力，用户再确认保存。网页关闭、跳转或取消请求时，未保存的复核失效。若网络已经存在，会沿用保存的配置。此流程支持 18 位精度的 EVM 原生币，网站图标下载暂未支持。[EIP-3085](https://eips.ethereum.org/EIPS/eip-3085)

网站需要切换网络时，由已连接站点另行提交 `wallet_switchEthereumChain`。批准后保留原账户并切换链，取消该站点在旧链上尚未完成的请求。未知或停用的目标链返回 `4902`。添加网络成功只代表配置已保存。[EIP-3326](https://eips.ethereum.org/EIPS/eip-3326)

### 配对本机浏览器扩展

1. 在项目根目录执行 `npm run build:wallet-browser`。Chrome / Edge 的扩展管理页开启开发者模式，选择「加载已解压的扩展程序」，打开 `dist/wallet-browser`。这份开发产物尚未在扩展商店发布。
2. 打开「设置 → 钱包 → 浏览器扩展」，或在 TUI 中打开 `/wallet` → 浏览器扩展。开启连接器、生成配对地址，并复制到扩展弹窗。可为不同浏览器配置填写容易辨认的名称。地址一次有效，未使用时两分钟过期。
3. 对照扩展弹窗和钱包中的浏览器身份指纹，确认扩展来源，再批准配对。刷新网页后，仍需在「应用连接」单独选择该站点能使用的账户和网络。每个浏览器配置的站点授权相互隔离，也与主机 Playwright 分开。

连接器只绑定本机 `127.0.0.1`，启用后随共享后台恢复。应用的连接身份使用 Windows DPAPI 或桌面的系统密钥环加密；macOS / Linux 的纯 Node 后台没有桌面密钥环适配时不启动连接器。扩展在自己的 IndexedDB 中保留不可导出的 P-256 密钥，先核验应用身份，再签署请求。随机挑战、会话标识和顺序编号绑定双方的每条消息。扩展无法获得钱包私钥或后台管理令牌。仅对顶层 HTTPS 页面和本机测试页面提供接口。

停用会断开浏览器，保留配对供以后恢复。撤销某个浏览器会断开它并删除其站点授权。扩展内「忘记此配对」清除当前配置中的连接和密钥；应用侧仍应撤销对应条目。断线不会自动重发任何请求。Chromium 的同一文档显式重送相同交易 ID 时读取已保存结果；相同消息签名 ID 跨连接再次请求时需先查钱包历史，扩展不会再次返回原签名。

本轮用实际 Chromium 验证加载和交易；Firefox 清单有兼容配置，尚未验证实际安装和签名。跨设备、VM 浏览器及硬件钱包不在此次范围内。[Chromium 的内容脚本隔离](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) · [Firefox 的 MV3 后台配置](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background)

## 应用登录与消息签名

已连接站点可通过 `personal_sign`（十六进制内容、账户）及 `eth_signTypedData_v4` / 对象格式的 `eth_signTypedData`（账户、结构化数据）请求签名。需要先在钱包页解锁；站点不能通过请求解锁或取得私钥。GUI / WebUI「设置 → 钱包 → 消息签名」和 TUI `/wallet` → 消息签名共用请求、历史及只读回执。逐笔复核实际来源、账户、链、验证合约和完整内容，再单独确认签署。交易自动授权不会批准消息签名，也没有 Agent 或公开 JSON action 可直接准备 / 释放签名字节。[EIP-191](https://eips.ethereum.org/EIPS/eip-191) · [EIP-712](https://eips.ethereum.org/EIPS/eip-712)

结构化签名可能是代币许可或其他链外授权，并不天然等于“登录”。验证合约地址只按请求原样显示，不表示身份已经证明；消息没有声明链时单独提示跨链重放风险。签名不占用交易 nonce，也不受现有交易签名预算约束。锁定、全局停止、页面关闭和断开连接可阻止尚未释放的请求，但不能撤销已由站点保存的签名；有效期、nonce 消耗和链上撤销仍由对应协议决定。`signed` 仅说明签名已生成，不能证明远端完成登录或链上授权。

识别到以太坊登录消息时，会核对其声明的来源、账户、链、nonce、时间字段与可识别的有效期。来源不匹配、已过期或尚未生效时拒绝进入审批。依赖方仍需验证签名和登录挑战，并防止重放；不能只信任钱包显示的“登录”标签。隔离浏览器夹具同时验证了站点验签和登录 Cookie。[Sign-In with Ethereum](https://eips.ethereum.org/EIPS/eip-4361)

消息摘要由宿主和原生签名器独立计算、交叉核对；人工批准绑定内容、实际站点、连接、所选链、账户、期限和当前原生解锁会话。回执在返回前加密落盘。宿主历史位于 `messages.json`，保留原始请求、摘要、拒绝 / 取消状态和回执标识，不保存明文签名字节；原生签名字节单独使用认证加密保存。锁定后的「只读核对回执」不重新签名、不广播，也不向网页释放签名。完整备份应同时保留宿主记录、密钥库及原生回执库。

当前每条请求上限 32 KiB，JSON 最多 32 层 / 4096 个节点，最多 64 个类型、256 个字段及 4096 次依赖展开；编码前另检查标识符、类型文本长度和数组维数，避免畸形声明耗尽签名器。支持嵌套结构、数组和字符串形式的完整 256 位整数；超过 JavaScript 安全范围的 JSON 数字会拒绝，避免静默舍入。域字段限标准 name / version / chainId / verifyingContract / salt，拒绝未声明或可能被忽略的字段；仅签名域的请求不能夹带不会签入摘要的非空正文。递归类型图、旧 v1 / v3 格式、`eth_sign` 原始摘要签名仍不支持，会明确失败。全局最多 16 条待处理消息，历史最多 2048 条 / 16 MiB；超额明确报错，不自动删除历史。浏览器昂贵请求还受每文档 8 / 共享后台 64 并发限制。原生库已有签名而宿主历史文件丢失时，会报告缺失，不能把它显示为全新的空历史。

## 开始使用

1. 打开侧栏的量化工作台，创建项目，选择 Base 或公开交易所行情。也可导入 CSV / JSON 历史数据。
2. 运行研究模板，查看成交假设、费用、滑点、权益与回撤。导入的数据不会被标记为已经验证的交易所数据。
3. 默认使用研究对话的 Agent · Goal，清楚说明目标和预期交付物。普通对话可关闭该开关。
4. 如需实盘，在设置的钱包页创建或导入钱包并解锁。默认在每笔交易的授权卡片中检查地址、金额、费用与调用信息。自动实盘授权必须由用户在钱包页手动完成。
5. 查询链上交易状态。提交、打包、安全确认、最终确认和回滚不是同一状态；不把广播成功当作兑换完成。

Base 兑换工具当前使用 WETH，不会把原生 ETH 与 WETH 混为一谈，也不自动执行隐含的包装或跨链操作。池费率可配置；自动发现与手填地址均校验官方 Factory 的部署来源。先验证报价及最低可得数量再申请精确代币授权，授权入块后重新报价。RPC 可使用自建节点；公共 RPC 仍然有运营方依赖。

## 合约查询与结果引用

`quant_contract` 的 `read` / `simulate` 会核对网络身份，将调用固定到选定的主链区块，并返回区块号、哈希、时间和 `ref`。`block` 可选择 `latest`、`safe`、`finalized` 或十六进制高度；重组或查询期间改节点配置时拒绝保存结果。模拟不签名、不广播，也不保证未来实际执行成功。ABI 名称与 RPC 返回内容属于外部输入，不代表合约身份或节点真实性已证明。[区块哈希调用规范](https://eips.ethereum.org/EIPS/eip-1898)

读取后续内容使用 `action="result"`、同一 `ref`、`offset` 和 `maxChars`，从不可变归档分页，不会混入新链状态或额外发起 RPC。`maxChars=0` 返回该归档范围内完整文本；重新调用 `read` 才是一次新观察。结果绑定研究工作区，校验哈希，重启、钱包锁定或网络停用后仍可读取。返回的 `observedAt` 是查询时间，`blockTimestamp` 是区块时间；历史结果不能当作当前可执行报价。

归档位于量化数据的 `contract-results` 目录，建议随研究数据备份。每条上限 2 MiB、共享后台最多 512 条 / 128 MiB，达到限制会报错，不会静默删除旧结果。当前尚无专用归档管理界面；需要保留的引用可从研究对话的工具记录读取。停止任务会取消进行中的节点请求，单次整体限时 30 秒。

## 链上代币授权

组合预算详情的「组合持仓」读取成员钱包在同一区块的 ETH、USDC、WETH，以及该组合累计和周期权限内的代币。界面显示按资产汇总的数量，并可展开成员明细。请求最多并发 4 个 RPC，45 秒整体超时。余额缺失时汇总标为不完整，已知数量单独列出。组合修订在读取期间变化或区块重组时拒绝旧快照。Agent 可以通过 `quant_portfolios(action="holdings", portfolioId=...)` 读取汇总，按需开启 `includeMembers`。

组合持仓的「读取参考估值」可按需追加 Base 主网 ETH / WETH 与 USDC 的 Chainlink 美元参考值。默认只读数量；选择估值后刷新会同时更新余额和价格，二者固定在同一区块。来源详情显示馈送合约、更新时间、价格年龄和排序器状态。USDC 使用实际馈送价格，并注明稳定币上限馈送，不假定始终等于 1 美元。其他代币和 Base Sepolia 没有配置美元价格，不将测试资产换算成真实美元。[价格接口](https://docs.chain.link/data-feeds/api-reference) · [官方馈送目录](https://reference-data-directory.vercel.app/feeds-ethereum-mainnet-base-1.json)

价格源读取失败、价格非正、精度异常、过期、区块超过 5 分钟、排序器离线或恢复不足 1 小时时，相关估值不可用。馈送年龄上限为官方心跳加 5 分钟容差：ETH 25 分钟、USDC 24 小时 5 分钟。价格与数量均保持整数运算，每钱包每资产按美元 8 位小数向下截断后求和，成员与组合总额一致。任一非零资产缺价或余额未知时完整总额为未知，单独显示已知部分估值；已确认零余额显示零。它是该快照区块的参考值，待确认交易、链外订单、后续费用与主动敞口限制仍需分别处理，已有累计签名预算继续独立计数。[L2 排序器与恢复宽限期](https://docs.chain.link/data-feeds/l2-sequencer-feeds)

GUI / WebUI 与 TUI 共用相同估值后端及三语状态。Agent 通过 `quant_portfolios(action="holdings", portfolioId=..., valuation=true)` 显式开启；`includeMembers=true` 可附带成员估值。行情查询不会解锁钱包、授予执行权限或触发交易。

组合持仓还显示「本地资金预留」：按每个成员在同一区块的余额与已入块 nonce，汇总本应用尚未消耗 nonce 的交易输入和费用估计。相同 nonce 的替换交易按各资产较大的占用计算，已计入该区块的操作不再重复扣除；发生重组时按新的 nonce 快照重新计算。汇总分别显示预留、扣除本地预留后的数量及不足状态，不使用其他成员的钱包余额掩盖单个钱包的缺口。读取期间本地交易资金状态变化会拒绝旧快照。[固定区块查询规范](https://eips.ethereum.org/EIPS/eip-1898)

新的标准 ERC-20 转出、本人 `transferFrom` 和已支持 Router02 精确输入兑换，在准备及签名前都会按共享本地账本核对余额、其他操作的预留和本次输入。预检查最多 30 秒，并要求区块不超过 2 分钟；余额 / nonce 不可用、预留不足或存在未解析的未完成调用时停止此笔代币操作。解析复用原生签名器，结果与完整交易和人工审批绑定。授权交易不按额度占用现金；费用仍占 ETH 预留。未签名的拒绝 / 到期操作可释放本地预留，可能已签名的取消 / 失败操作保留到原生回执对账或 nonce 证实已消耗。对账只读，不自动广播。

这里的剩余量仅覆盖本应用已知操作；不计其他应用、链外订单、既有 allowance 的潜在支出和任意合约内部行为。原生签名预算仍独立执行。

Base 主网的组合可在创建或编辑时设置「组合权益下限」，单位为 USD，留空停用，提交仍需 `ALLOW PORTFOLIO`。该项保存到原生组合修订，重启后继续生效。系统对同一区块的 ETH、WETH 和 USDC 扣除应用内待结算输入和费用预留，再按 Chainlink 价格估值。同 nonce 的替换按各资产较大的预留计算，转入、内部划转及兑换输出在链上到账后计入。现有授权的外部支出、其他资产、外部客户端及链外订单不在测算范围。

下限覆盖经应用发起的人工与 Agent 交易。余额、排序器、报价、nonce 或调用效果无法核实，或扣除预留后的估值低于下限时，阻止签名或广播。原生签名器核对复核记录所绑定的组合修订、交易、操作 ID 和时间；宿主在广播前用新快照再核对。已签名后被拦截的交易保留原生回执及已消耗预算，可从交易详情核对。可在组合详情检查当前估值，或让 Agent 用 `quant_portfolios` 的 `equity` 读取。该估值下限按检查时点执行，跨时点损益、链上强制限制和完整净敞口仍需单独处理。

钱包页可添加观察账户，填写名称与公开地址即可持久保存，支持资产和授权查询。本地密钥钱包使用创建或导入入口。观察账户显示独立状态，可移除其本地记录。可从观察账户的「导入密钥」入口绑定目标地址，普通导入同一地址也会自动升级。升级保留账户 ID、名称、创建时间和代币追踪列表，完成后需手动解锁。地址不匹配或观察记录在导入期间被移除时拒绝升级。账户状态保存失败会在串行写入队列内恢复密钥文件。

「资产总览」可切换已保存网络，按一个区块哈希读取原生币及每个网络最多 16 个额外代币。Base / Base Sepolia 另含 USDC、WETH 预设；自定义链不套用 Base 合约地址。追踪列表跨前端、跨重启共享。读取失败显示为不可用，自定义代币精度不可用时显示最小单位整数。此列表覆盖内置及手动追踪的代币，自动资产发现待接入。Agent 可用 `quant_base_inspect` 在 Base 项目下传入 `address`、`assets: true` 与可选 `tokens` 取得同样的只读快照；指定 chainId 时也可读取已登记自定义 EVM 网络。[ERC-20 余额与可选元数据](https://eips.ethereum.org/EIPS/eip-20)

在钱包账户里打开「链上授权」，选择 Base 或 Base Sepolia，填入 ERC-20 代币合约和获准支出的地址。锁定时也能查询。结果显示观测区块和原始额度，USDC、WETH 按该网络内置的代币精度显示。量化 Agent 可用 `quant_base_inspect`，同时传入 `address`、`token`、`spender`。查询使用区块哈希固定的 `allowance(owner, spender)`，需要支持该参数的 RPC。[ERC-20](https://eips.ethereum.org/EIPS/eip-20) · [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898)

「查找历史授权」按所选钱包地址扫描链上 `Approval` 事件。默认查最新 1,000 个区块，可指定结束区块与 1–2,000 的扫描数量，或翻到更早的区块。每个窗口按合约与 spender 去重，显示该窗口内最后一次事件。选中后会查当前额度，因为历史事件的金额可能已被消费或覆盖。扫描覆盖以显示的区块范围为准，并受 RPC 日志查询限制。量化 Agent 可以用 `quant_base_inspect` 传入 `approvalHistory: true` 和公开钱包地址做同样的只读扫描。[Ethereum 日志查询](https://ethereum.org/developers/docs/apis/json-rpc/#eth_getlogs)

选择 Permit2 可以在同一区块查看 AllowanceTransfer 的额度、到期时间、nonce 和代币授予 Permit2 的额度。界面按两层额度中的较小值显示当前上限，到期后为零。实际可转出的金额还取决于代币余额及合约行为。历史扫描包含 `Approval`、`Permit` 和 `Lockdown`。量化 Agent 可在同一工具传入 `protocol: "permit2"`。[Uniswap AllowanceTransfer](https://developers.uniswap.org/docs/protocols/permit2/concepts/allowance-transfer) · [官方部署](https://developers.uniswap.org/docs/protocols/v4/deployments)

归零按钮会先模拟 ERC-20 的 `approve(spender, 0)` 或 Permit2 的单组 `lockdown`，模拟通过后放进待审批列表。解锁后仍需核对代币合约、spender 和预计费用，再人工确认签名广播。确认后重新查询额度。Permit2 `lockdown` 清除当前支出额度，保留底层代币授权及 nonce。有效的旧签名许可仍可恢复额度。可以切回 ERC-20 查询并单独撤销代币授予 Permit2 的额度。[Permit2 合约实现](https://github.com/Uniswap/permit2/blob/main/src/AllowanceTransfer.sol)

Permit2 的「准备作废当前许可签名」将选定代币与 spender 的已观测 nonce 加一，作废低于新数值的额度许可签名。准备时再次检查当前 nonce，变化后需要重新查询。审批卡列出新数值。此操作保留当前额度，已有授权可通过单独的归零交易清除。交易确认前签名仍可能被使用，确认后应复查额度和 nonce。[AllowanceTransfer 撤销实现](https://github.com/Uniswap/permit2/blob/main/src/AllowanceTransfer.sol)

「Permit2 单次转账签名」按用户输入的签名 nonce 读取 SignatureTransfer 位图，可输入完整十进制或 `0x` 十六进制。准备撤销时只设置对应的一位，并在签名器中核对单个位掩码。已使用与已撤销在位图中均为不可用。该操作由用户人工准备、审批，独立于额度许可 nonce。工具 `quant_base_inspect(address, signatureNonce)` 可只读查询此状态。尚未广播的离线签名无法从链上自动枚举，需从签名记录取得 nonce。[SignatureTransfer nonce 规则](https://developers.uniswap.org/docs/protocols/permit2/concepts/signature-transfer#nonce-schema)

### 组合链上授权敞口

在 Base 或 Base Sepolia 的「钱包 → 组合预算 → 链上授权敞口」扫描最近区块、逐段补扫历史，或只复核已知授权。GUI、WebUI、TUI 可以读取已保存的快照。量化 Agent 可用 `quant_portfolios` 的 `allowances_scan`、`allowances_get`、`allowances_list` 分页查询，通过 `candidates` 补充已知的钱包、代币、spender 和协议组合。扫描默认覆盖 USDC、WETH 和组合规则内的代币，也可指定单个代币。

每份快照在同一个区块读取余额和有效额度。每个钱包的已核对敞口按自身余额封顶，多个 Permit2 内层授权共用代币授予 Permit2 的外层额度。界面单独列出计入全部外层额度的条件容量，仍只计算本次候选范围内的 ERC-20 直接授权。链上扫描无法枚举尚未提交的离线签名。可以从任何历史快照打开单笔授权，按最新区块重新读取，再走现有人工撤销流程。[ERC-20](https://eips.ethereum.org/EIPS/eip-20) · [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898) · [Permit2](https://developers.uniswap.org/docs/protocols/permit2/concepts/allowance-transfer)

扫描每次最多 2,000 个区块，每个钱包和协议读取至多 50 个发现候选，每份快照保留至多 256 个候选及自动复核的外层授权。读取失败或达到候选上限时显示部分结果，可缩小区块或代币范围后重试。报告按组合保存，支持 SHA-256 校验和重启后查阅，每个组合最多 256 份。继续扫描会核对上一次快照的链上区块哈希。组合成员或代币范围变更后需从新快照开始。授权快照是只读风控证据，实盘仍由配置的预算、权益下限和审批规则控制。

在「持续监控」中选择一份读取完整的近期快照作为基准，然后设定 1、5 或 15 分钟复核间隔。监控随共享后台启动，可在钱包锁定时运行。最多保存 32 个组合的监控配置，各保留最后一次完整快照和最近 30 条变化记录。后台恢复后从上一个已核对区块开始逐段补扫，节点需要能读取对应历史区块的代币状态。遇到 RPC 失败或扫描不完整会退避、缩窄区块窗口并从原进度重试。基准失去主链状态或监控范围不再匹配时需人工选择新快照。Agent 可通过 `quant_portfolios(action="allowance_monitor")` 读取监控状态及分页记录。

监控通知记录在观测区块仍可见的授权或敞口增加。两次观测之间已恢复的临时变化和未提交的链外签名可能无法看到。选择变化记录中的授权对象可以重新读取当前状态。开启监控只会发出链上读取请求并保存证据，执行权限仍遵守钱包设置和人工审批。[EIP-1898](https://eips.ethereum.org/EIPS/eip-1898) · [Permit2 授权规则](https://developers.uniswap.org/docs/protocols/permit2/concepts/allowance-transfer)

### 组合授权总额度上限

在「链上授权敞口」选择完整的近期快照，再打开「授权总额度上限」。每个 Base 或 Base Sepolia 组合可选一个代币，额度填 `0` 可阻止该代币的授权增加。开设、改额或移除上限均需原有组合二次确认。限额与组合修订一起保存在原生签名器中。

标准 `approve` 增额会在签名和广播前分别检查。计算把各钱包已知的 ERC-20 授权相加，每个授权对象按当前值、本地未结算授权及拟变更值计算。对 Permit2 只计 ERC-20 外层额度，代币余额为零时也计算这笔授权。上限启用后，减少已有额度的操作仍可通过这项检查。节点读取失败或基准落后超过 2,000 个区块时暂停该次增额。可启用基于同一快照的监控补齐区块，或更新基准。[ERC-20](https://eips.ethereum.org/EIPS/eip-20) · [Permit2](https://developers.uniswap.org/docs/protocols/permit2/concepts/allowance-transfer)

上限的统计范围以快照、后续日志、组合规则、本地在途交易和本次授权对象为准。钱包外部签发或广播的交易、未提交的许可签名和任意合约中的授权副作用不受这项控制。既有钱包审批、交易预算和实盘自动授权分别执行。

### 组合成交损益

在 Base 或 Base Sepolia 的组合详情打开「成交损益」。报告使用当前成员钱包已有的实盘计划成交记录，按各钱包的交易 nonce 顺序做先进先出配对。页面可筛选成员，查看买入、卖出、已分配成本、成交收入和 USDC 毛损益。费用以 ETH 单列，显示 L2 执行费、L1 数据费及运营费的回执覆盖率。

已确认的成交缺少证据时，后续计算会从下一笔有证据的买入重新建立配对。无法配对的卖出单独显示数量。成本按代币最小单位分配，数据涵盖本应用实盘计划的 WETH / USDC 成交。Agent 可用 `quant_portfolios(action="performance")` 查询同一视图，翻页时可用 `snapshotId` 核对数据版本。[链上交易回执字段](https://ethereum.org/developers/docs/apis/json-rpc/#eth_gettransactionreceipt)

Base 主网可点「折算历史费用」，按交易最终确认的区块读取并保存 Chainlink ETH/USD 与 USDC/USD 报价轮次。折算以 USDC 最小单位向下取整，按配对数量分摊买入和卖出费用。全部配对成交的费用都有证据时显示扣除兑换费用后的已实现损益。授权和失败交易的费用计入单独的计划费用汇总。报价过期、排序器不可用或节点缺少历史状态时保留缺口。Agent 可用 `quant_portfolios(action="performance_price_fees")` 分批折算。[Chainlink 数据接口](https://docs.chain.link/data-feeds/api-reference) · [区块哈希查询](https://eips.ethereum.org/EIPS/eip-1898)

## 新闻研究与决策建议

研究 Agent 现在可以通过 `quant_news_search` 使用已配置的搜索引擎，通过 `quant_news_fetch` 阅读公开 HTTPS 来源。请求在主机执行，复用应用网络 / 代理配置，不启动 VM 或浏览器，也不携带钱包凭据。默认检索返回少量摘要，正文按需分页；`maxChars=0` 可读取网络大小上限内的完整内容。引擎选择、自己的 Provider 和 Key 沿用现有网络研究设置。

当前分析可调用 `quant_inspect(refresh=true)` 请求更新行情；`asOfUTC` 只是检查时钟，不能代替报价的观察时间、事件时间和质量检查。新闻、K 线或 AMM 采样也不能代替实盘工具的重新报价与模拟。

提示词引导它优先核验公告、治理、交易所状态、官方经济发布等一手资料，区别发布时间 / 事件时间 / 检索时间，以及事实 / 推断 / 假设。建议应说明消息的影响机制、是否可能已被定价、反证、情景条件、仓位约束、失效条件和成本；不能把转载数量当成独立验证，不能编造收益、概率或已经部署的持续任务。明确且具备条件的已授权实盘操作不以反复搜新闻或模拟为额外门槛。

成功的搜索与实际读到的网页片段会单独保存为带 SHA-256 的研究证据。GUI / WebUI 的「研究证据」页和 TUI `/quant` 项目菜单均可查看。归档不随网页缓存过期；正文片段不会被标记成全文。Agent 可以用 `quant_history(kind=research)` 找到证据 ID，再读取原先的片段。页面自报日期不等于已证实日期；无日期时显示未知。

新闻是待核实数据，不能授予签名 / 支付权限或扩大交易范围。外部服务故障与「没有相关新闻」不同：例如 HTTP 429 会显示搜索限流，不会被当成否定证据，也不盲目重试。网页读取会拒绝本机地址、IP 字面量、含凭据 URL、非标准端口及降级重定向；这不是对任意 DNS 重绑定的防火墙保证。

研究流程参考 [CFTC 关于 AI 交易机器人的提示](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/AITradingBots.html)及 [Investor.gov 关于核验社交媒体来源的提示](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-alerts/social-media-and-investment-fraud-investor-alert)。工具链、来源保护、分页、重启与 GUI 交互已验收；这不证明所有真实模型都能给出高质量市场判断，后续需按[研究评估清单](quant-research-evals.md)持续验证。

## Goal

Chat / Code 可输入 `/goal <目标>`，或使用 `/goal status`、`/goal pause`、`/goal resume`、`/goal clear`。Agent 只有调用完成工具并提供完成说明后，才将目标标为完成。用户停止、额度用尽、错误或轮数限制会中止继续执行，不会伪装成完成。

恢复旧会话时，未完成 Goal 会恢复为暂停，避免重新打开历史就执行交易。Goal 不能替代钱包授权。

## 数据和执行边界

- 当前回测是现货、只做多的 K 线研究模型：上一根收盘产生信号，下一根开盘执行，计入费用与滑点。没有盘口队列、市场冲击或高频成交精度。
- 研究账户的采样仿真订单采用完整成交假设；下述原生仿真账户另有连续队列与部分成交模型。重启后均不补造离线成交。
- Base 行情是链上池价格采样，没有真实成交量；导入 OHLC 与交易所行情分别标记。
- Rust 原生库已有 18 位金额、带序列和时效检查的 L2 盘口、独占持久日志、共享资金预留、部分成交与手续费累计舍入；进程接口可提交和撤销独立仿真意图。成交接口不向前端或 Agent 开放；当前前端研究账户仍使用上述完整成交假设，没有因此获得原生撮合能力。
- 原生进程的盘口撮合服务仍为 **仿真**：保守的同价 maker 队列支持延迟、去重、部分成交和一事件多成交的原子落盘。Coinbase 公共连续行情、原生账户、独立被动做市 PAPER / SHADOW、固定版本事件回放与三端操作已接入共享后台。Base 串行实盘拆单通过独立发件箱连接 WalletService，并使用原生签名器；它不把仿真撮合变成交易所实盘。更多策略、真实 HFT 延迟指标、中心化交易所实盘连接、跨链执行、硬件钱包及其他链签名器仍未完成。不能把 Base 现有支持称为“任意链全部兼容”。

## 原生仿真账户与订单

GUI / WebUI 在量化工作台选择项目后点击「原生仿真账户」；TUI 入口为 `/quant` → 项目 → 原生仿真账户。连接内核与行情，创建带名称、初始虚拟资产和明确风险上限的账户，或选择已有共享账户。账户默认暂停，启用后才能提交 Post-only 限价单。500 毫秒延迟和保守队列只是仿真假设。

资金、预留、订单、每一笔部分成交及本笔费用由同一原生账本管理。账户可供多个项目共享，账户暂停影响其全部策略；订单和成交历史按项目过滤，切换账户不会隐藏旧记录。暂停 / 断线 / 重启留下的挂单保持预留并标为挂起，恢复不会重新排队；先撤销旧挂单，再按需创建新意图。

共享后台在发出新单前持久保存待核对记录。确认丢失会保留记录并阻止该项目换标识再发新单。恢复健康账本后，「核对上次提交」只查询：已记录则返回原单，确实不存在则解除待核对状态，不自动补单或恢复交易。原生账户创建也按初始定义去重，不会在重试时重置已经变化的余额。两份存储不是一个跨进程原子事务，核对流程负责衔接其失败窗口。

Agent 的 `quant_native_paper` 工具走同一后台和项目范围；逻辑操作 ID 跨工具重试及研究会话恢复保持一致。此工具可管理账户、行情和仿真限价单，不能注入成交、取得密钥或绕过实盘钱包权限。

## 独立策略

GUI / WebUI 工作台选择「原生策略」，TUI 选择项目中的同名入口；Agent 使用 `quant_strategy`。先建立原生账户与行情，再定义被动做市参数、库存范围、累计成交额 / 费用 / 决策上限。PAPER 提交仿真订单；SHADOW 只记录信号，不创建订单或成交。原生进程独立评估，不逐 tick 调用 LLM。

修改参数创建新的不可变版本，已有运行固定原版本。停止只影响该次运行的委托；行情失效和重启暂停，挂起订单继续占用预留，不自动重建队列。历史保存决策、委托结果及逐笔成交；其他策略与独立实盘桥接仍待完成，也不证明 HFT 性能或盈利。仿真撤单未模拟网络延迟。

## 原生账户紧急停止

原生仿真账户面板和 TUI 的同名账户菜单提供「紧急停止并撤单」。它影响共享这个账户的所有项目：取消剩余挂单、释放订单预留、停止 PAPER / SHADOW 部署，并用单条原生账本事件持久保存停止锁。已成交数量、费用、余额和历史保留，其他账户继续按原状态运行。

停止请求直接进入控制通道，不等待宿主普通下单队列。原生端仍按顺序处理命令和成交；停止前已经发生的成交不会被回滚。存储故障时明确返回失败或未知结果，并保持执行暂停，不谎报已撤单或释放资金。

Agent 可用 quant_native_paper 的 halt 动作停止所绑定账户，必须保留同一次请求的 operationId；它没有解除锁定的工具权限。GUI / WebUI / TUI 解除操作需要明确确认，并核对当前账户和停止锁标识；账户或锁变化后旧确认失效。解除后账户仍暂停，已撤订单和已停止策略不会自动恢复。

此控制针对原生仿真账户；实盘钱包的锁定和自动授权仍由钱包服务独立管理。它不表示已经具备所有交易场所的实盘批量撤单或全产品应急停机。

## 行情记录与事件回放

GUI / WebUI 的项目工具栏选择「行情记录与事件回放」，TUI 在项目菜单进入同名页面；Agent 使用 quant_event_data 工具。先连接公共行情，录制时从该连接的串行队列取得一致的有界快照，再保存规范化盘口、成交与失效输入。不会重启行情或改变当前订单。

结束录制后刷盘，保存文件与元数据 SHA-256；失败或中断的记录不能直接运行回放。当前单条最多 256 MiB、24 小时，同时最多四条；超额或写入背压明确失败，不悄悄丢数据。尚无自动归档、压缩或配额清理；长期运行前需检查磁盘空间。

选择一条完整记录、策略及版本号，后台固定其版本链、市场规则、当前引擎二进制摘要、风险和初始虚拟资金。默认复制所选原生仿真账户的**可用**余额；工具也可明确提供实验初始资金。回放使用独立进程与账本，不扣原账户余额，不持有实盘凭据或连接交易场所；同一后台同时运行一个回放实验。

虚拟时钟复用现有原生策略、资金预留与 FIFO 撮合，按 50ms 调度推进；没有行情的时间段也推进时钟并执行过期暂停。完成后撤销该实验的仿真挂单，保存决策、订单、每笔成交、费用、拒绝事件和账本摘要。界面 / 工具可取消、查看进度、读取分页历史；Agent 状态查询支持最多 30 秒等待，避免连续空查询。

选择一条已完成且带结束时点的记录，在「盘口滚动样本外验证」选择同一策略的 2–4 个已保存版本，填写距录制开始的偏移、训练与验证时长（毫秒）以及 1–4 轮。每轮向后滑动一个验证窗口长度。原生引擎在窗口开始前只预热行情，按左闭右开的区间执行策略。每个训练和验证回放都从同一份仿真资金和风控配置独立启动，因而各轮结果适合并列比较。资金、挂单和策略运行状态不会跨轮累加。

训练按扣除成交费用后的交易贡献排名，贡献相同则按较低费用和较早版本决定顺序。每轮只将训练第一名放入后续验证窗口。交易贡献按窗口末尾的有效盘口中价估值。没有窗口内事件、回放拒绝了行情或缺少有效末尾盘口时，实验停止并保留已经完成的轮次。报告固定录制哈希、候选版本、二进制摘要和风控，并可分别查阅各候选及验证的订单、成交、决策。Agent 使用 `quant_event_data` 的 `replay_validate`，通过 `replay_history` 指定 `fold`，可另加 `trainingRevision` 查看训练证据。窗口最短 500 毫秒，最终窗口须在录制前六小时内；还受 32 MiB、累计扫描 50 万事件及累计虚拟时间 24 小时限制。

「交易贡献」是相对实验初始资产数量的增量，按末次有效盘口中价估值，已计入仿真成交费用；它不等于已实现利润。末尾没有有效报价时不计算该估值。原有库存本身的价格涨跌不被当作策略交易贡献。

这是**主机适配器输入时间**上的历史实验，不是实盘命令 / 回报时间的精确复演；也没有全部原始交易所数据、L3、市场冲击或撤单网络延迟。500ms 到达、同价 L2 FIFO 和立即仿真撤单仍是明确的模型假设，不是 HFT 成交精度或收益保证。原生分发已接入六平台构建，本地已验证 Windows x64 实际安装资源；其他平台仍待原生 CI 验收，尚未发布这些新功能。

## 原生连续行情

在量化项目设置中先连接原生进程，再选择「公开连续行情」中的交易对和模拟 Maker 费率，连接后可查看连续盘口。GUI 与 WebUI 使用同一界面；TUI 入口为 `/quant` → 原生执行进程 → 公开连续行情。当前支持 ETH-USD、BTC-USD、SOL-USD；这是交易所公共现货数据，不是 Base AMM 的可执行报价，也不会创建账户或开启真实交易。

连接器订阅 [Coinbase 官方公开频道](https://docs.cdp.coinbase.com/coinbase-app/advanced-trade-apis/websocket/websocket-endpoints)，核对整条连接的消息序列，再分别生成内核盘口与成交序列。它使用价位的绝对数量，并区分成交的 maker 方向；初始历史成交快照不会用来撮合。只有盘口、成交与心跳初始化完成并追平当前数据后，盘口才可执行。丢失消息、无效数据、积压或网络政策变更会失效当前盘口；恢复快照不会自动重建或重新激活旧委托队列。

大型初始快照可能落后于实时流，因此先完整追平，不把接收时间冒充行情发生时间。原生盘口只保存明确覆盖范围内的价位，范围外不假定为空队列。延迟数据和心跳失效不能继续下单；暂停或断线后原生未完成意图保持挂起及资金预留，需要后续显式处理。

连接器通过公开的交易所时间接口估算时钟差异及请求往返误差，保守地把事件投影到主机时钟，不修改系统时间。内部 `sourceTimeNs` / 成交 `time_ns` 是保守映射时间；`providerTimeNs` / `provider_time_ns` 保留原始交易所纳秒时间，`sourceClock` / `source_clock` 记录映射、误差范围及校准时刻。内核校验映射一致性和校准时效；本机时钟跳变会停止当前流。这是带假设的纸面撮合模型，不是经过认证的时钟或 HFT 性能保证。

HTTP 和 WebSocket 均在主机使用应用的网络 / 隐私配置。每条流拥有自己的传输实例，网络设置变化会立即断开旧连接；隐私通道未连接时不回退直连。停止原生进程会停止全部数据源，进程故障不自动重启交易或重复金融命令。三端共享连接状态，不因多开前端创建多份原生进程。

各交易对共用一个有界订阅队列，发送间隔至少 250 毫秒，避免多端同时连接或重连时集中发送订阅。状态保留连接尝试次数、延迟挂起次数及实际处理成交数；迟到行情恢复可读不代表旧的挂起订单已经恢复执行。

- 本机用户自己的任意脚本或 Shell 与程序拥有同级系统权限，应用内策略不是抵御同一系统用户恶意代码的操作系统隔离边界。

## 发布包检查

`npm run check:runtime-deps` 使用打包器实际收集的生产依赖，检查普通依赖和必需 peer 依赖，并隔离加载 DSH、插件宿主和 Claude SDK。打包后再次检查最终归档，并用安装包自带 Node 启动真实后台。检查禁止借用开发仓库中的模块。

本轮修复了必需 DSH 组件仅在开发环境可用、发布包缺少 `dsh-session-title` 等模块的问题。必须以新构建的安装包验证结果为准；已有下载文件不会因修改源码自动修复。

原生量化运行时固定 Rust 工具链和六个目标，在各平台 CI 主机编译。Windows 静态链接 CRT，Linux 使用 musl 静态可执行文件，macOS 在压缩前签名。程序以压缩资源和清单随应用分发，首次启动前核对压缩包与原始程序的 SHA-256、大小、协议及实际架构，再写入用户私有的按内容哈希隔离的缓存；运行时不需要 Rust 或在线安装依赖。

缓存版本互不覆盖；损坏缓存只从验证通过的资源修复。安装资源缺失或校验失败时明确拒绝启动，不借用开发仓库的程序。macOS 本地重新签署整个 App 不会改写压缩资源内的程序，因此不会破坏其校验哈希；这一点已有签名目标扫描测试，但不替代真实 macOS 签名 / 公证验收。旧缓存的自动清理仍待实现。

## 实盘全局停止

GUI / WebUI 在「设置 → 钱包」使用「停止所有实盘」；TUI 在 `/wallet` 菜单选择同名操作。它覆盖 CIBYP 的所有钱包和工作区：先保存独立停止记录、关闭解锁会话、阻止新签名和广播，再异步暂停原生实盘计划；停止不排队等待普通钱包操作，不暂停 PAPER 账户。正在暂停或失败会单独显示，失败可重试，不能据此声称所有链上交易已取消。

已广播或结果未知的交易保留哈希、费用和历史，停止期间仍可读取余额、核对结果和导出加密备份；已有链上代币批准不会被本地停止撤回。未广播意图取消或被代次屏障阻止，不能因为后来解除停止锁而重新发送。

解除需要先阅读说明，再输入 `RESET LIVE` 二次确认；原生暂停尚未确认时不允许解除。解除后钱包仍锁定、权限为逐笔人工确认、计划保持暂停；重新解锁、授权和启动都须单独进行。停止前的自动授权绑定旧代次：只恢复旧钱包状态文件也不能使其重新生效。此保护依赖独立停止记录仍存在；不声称能抵抗操作系统同用户任意代码或整个存储目录回滚。

停止记录使用校验和、同步写入及原子替换；记录损坏时关闭钱包执行能力。写入失败仍保持当前进程的停止屏障，但不能承诺这次停止已跨重启保存；界面提示修复存储并重试。

Agent 的 `quant_live_control` 只有 `status` / `halt`，没有解除、解锁或授予权限的动作。单个计划停止仍用 `quant_live_execution stop`；全局动作应符合用户的全局停止指令或明确风控授权。此控制不取消交易所订单、不撤回其他钱包客户端的操作，也不保证极端行情损失。

## 可复现验证

GUI / WebUI 在量化项目工具栏选择「实盘计划」，TUI 从项目菜单进入同名页面。选择钱包、买卖方向和调度方式，再填写输入金额、段数、间隔、滑点和累计预估费用预算。计划创建后默认暂停。启动需要手动授予的自动实盘范围和已解锁的钱包。面板显示最终确认进度、费用预留、执行记录与哈希，并提供停止和只读对账。Agent 使用 `quant_live_execution`。关闭面板后后台继续调度。

首次启动时，原生账本会记录当时区块的 Uniswap V3 池内边际价、池地址、区块时间与哈希。暂停、恢复或重启后沿用同一参考价。按已核对成交的 WETH 数量计算 USDC 价差和基点，正值表示买入更贵或卖出更便宜。参考价来自启动时可见的区块，未成交部分和 ETH 手续费单列。旧计划如已启动过且没有启动快照，则继续保留原有记录。[启动价对比方法](https://www.interactivebrokers.com/campus/glossary-terms/arrival-price/)

可选填「启动价最大不利偏离」(`maxArrivalCostBps`)。例如启动价为 2,000 USDC/WETH，填写 25 基点后，买入上限为 2,005，卖出下限为 1,995。每段按对应输入金额将限额换算为最低输出，并向上取整。系统取启动价限额、最低总输出按比例分配的下限和报价滑点下限中最严格的一项写入兑换交易。报价超限会暂停计划，后续恢复沿用原限额和原参考价。留空时沿用原有滑点和输出设置。[Uniswap V3 路由最低输出检查](https://github.com/Uniswap/swap-router-contracts/blob/main/contracts/V3SwapRouter.sol#L85-L106)

计划和逐段历史按最终确认回执中的 WETH、USDC 净转账显示实际支出、到账和成交均价。未核对的段体现在成交覆盖率里。L2 执行 Gas、L1 数据费和运营费分别显示已覆盖的交易数，其中包括批准和最终确认失败的交易。运营费使用原成交区块的 GasPriceOracle 和实际 Gas 用量。三项费用均覆盖时显示已最终确认的总费用。签名前的费用预算使用按 Gas 上限计算的运营费估算。旧计划可用「核对链上结果」分批补取回执，操作可在钱包锁定时完成。[ERC-20 转账事件](https://eips.ethereum.org/EIPS/eip-20) [GasPriceOracle 接口](https://specs.optimism.io/protocol/isthmus/predeploys.html#gaspriceoracle) [Base Jovian 费用规则](https://docs.base.org/upgrades/jovian/exec-engine#operator-fee)

调度默认采用「最终确认后计时」(`schedule: "settlement"`)。选择「固定时间窗」(`schedule: "fixed-window"`) 后，第一次启动固定全部窗口。每段按原计划的输入份额在对应窗口内派发，上一段仍待最终确认时会等待。错过的窗口和输入金额单独记录，后续窗口沿用各自的原份额。到期时，部分执行的计划显示过期，仍可核对已提交的交易。后台重启后需要重新启动计划，仍沿用最初的时间表。[TWAP 调度参考](https://www.interactivebrokers.com/docs/general/order-types/algorithmic-orders/ib-algorithms/twap)

「历史成交量加权」(`schedule: "vwap"`) 沿用固定时间窗，按所选 Base 或 Base Sepolia Uniswap v3 WETH/USDC 池的实际成交量分配输入。先选择 2–96 段、最多两小时的计划，再获取并预览权重。系统从最终确认区块往前取三个与计划等长的时段，按相对窗口汇总 WETH 成交量。预览记录池地址、区块、时间范围和各窗权重。创建计划后权重固定，零分配窗口跳过，错过的输入保留。成交历史依赖项目配置的 RPC，限流或历史不足会提示错误。历史权重无法保证未来流动性或成交均价。[VWAP 调度参考](https://help.coinbase.com/en/prime/trading-and-funding/vwap-order-type) [Base 成交日志接口](https://docs.base.org/base-chain/api-reference/ethereum-json-rpc-api/eth_getLogs)

Agent 可用 `quant_live_execution` 的 `profile` 获取权重，`profile.get` 复核证据。建计划时提交同一项目、段数、窗口长度和 `profileId`。获取权重不需要解锁钱包，实盘启动仍受钱包授权控制。

计划结束并核对所有成交后，可选择「市场 VWAP 对比」。系统读取同一池从首笔至末笔成交区块的 `Swap` 日志，核对本计划的成交额并从市场样本剔除这些交易。市场均价以 USDC 总量除以 WETH 总量计算，正基点表示买入更贵或卖出更便宜。ETH 链上费用单列。基准随区块和成交证据保存。没有外部样本、RPC 无法提供历史、区间超过 120,000 个区块或日志超过 10,000 条时，界面会提示无法比较。Agent 可用 `quant_live_execution` 的 `benchmark` 操作计算或读取结果。[Uniswap V3 成交事件](https://github.com/Uniswap/v3-core/blob/main/contracts/interfaces/pool/IUniswapV3PoolEvents.sol)

固定时间窗同时限制钱包签名与发送，兑换 calldata 的截止时间也取窗口结束之前。已经广播的交易可以晚于窗口确认，已提交的 ERC-20 授权仍需核对。最终确认延迟较长时，固定时间窗可能只成交部分输入。累计费用为预估预算。[路由器截止时间实现](https://github.com/Uniswap/swap-router-contracts/blob/main/contracts/base/MulticallExtended.sol)

实盘计划可选填「最低总输出」。买入以 WETH 为单位，卖出以 USDC 为单位。引擎按每段输入所占比例分配最低输出，并向上取整到代币最小单位。交易使用该值和报价滑点下限中较高的一项。例如以 2.5 USDC 分两段买入，若设最低总输出为 0.001249 WETH，每段至少接收 0.0006245 WETH。固定窗口发生跳过时，已执行段仍使用各自的最低输出。计划与历史记录都可核对该值。Agent 创建计划用 `minimumTotalOutput`，单次兑换用 `minimumAmountOut`。[Uniswap v3 路由合约](https://github.com/Uniswap/swap-router-contracts/blob/main/contracts/V3SwapRouter.sol#L85-L106)

报价低于最低输出时，计划暂停。如果代币授权已经提交，后续报价仍要重新核对。钱包在签名前和广播前分别模拟实际交易。价格在广播后仍可能变化，低于链上最低输出时交易会回退，仍可能产生 gas。已确认的授权和已生成的签名回执可分别核对。

- `npm run test:wallet:browser-extension`：需先准备钱包签名器和 Chromium，在隔离浏览器配置中加载真实扩展，验证配对指纹、加密身份、分开的站点权限、人工消息签名和链上转账，以及断线后的重复请求和跨后台重启撤销。运行 `npm run build:node-core` 后，可用 `npm run test:wallet:browser-extension -- --bundled` 验证打包后台。
- `npm run test:quant:execution`：构建真实原生进程，在隔离 Anvil 上运行原生调度、加密签名、测试代币批准 / 转移、最终确认、费用预算、签名中停止 / 撤权 / 暂停 / 配置变更及隐藏确认后的重启恢复。合约为固定价格测试夹具；运行时校验源码和字节码摘要。打包验证可在 build:node-core 后执行 node scripts/test-quant-chain.cjs --execution --bundled；不依赖 Solidity 编译器、外部模型或真实资金。

- `npm run test:quant:native:bundle`：通过打包后的 Node 后台验证同一原生进程、账户绑定持久化、一致的账户 / 历史视图、重启暂停与进程回收；不发送网络请求或真实订单。
