本轮继续补齐原生签名回执：内部协议 2 要求持久库标识和操作 ID；签名器先在 SQLite 事务中提交回执，再返回可用签名。同一 ID / 同一交易可返回原签名，换交易内容则拒绝；签名字节通过 HKDF-SHA256 / XChaCha20-Poly1305 单独加密保存，锁定时只返回元数据和哈希。数据库采用 EXTRA 同步及 fullfsync 请求，持有单写者锁，启动检查完整性、计数和全部回执校验；写入失败后须重启恢复。同步可靠性仍取决于文件系统和硬件，校验不能阻止管理员恢复一份内部一致的旧备份。

后台在调用签名前保存绑定，崩溃后的无哈希操作改为“签名结果待核实”，不再直接判过期；nonce 和预算继续预留。只读对账可在钱包锁定 / 撤权后恢复哈希，查询链上结果，绝不自动重新签名或广播。回执丢失 / 损坏 / 换库、旧版本没有回执绑定时保留未知状态；仅原库完整性检查后的确定缺失才能释放未签名预留。GUI / WebUI 的详情与 TUI 菜单均可发起对账，三语说明同步；后台关闭会等待签名器退出及文件锁释放。

后续本轮已接入内部协议 3 的原生授权：逐笔审批绑定完整交易哈希、准确费用预留、期限和原生解锁会话；缓存签名也必须重新核对现有权限。自动授权在 Rust 中核对钱包、实际签名地址、链、期限、费用上限及持久撤权代次；迟到授权不能覆盖较新撤权。原生控制命令只经可信后台私有管道调用，不能从普通钱包 action 或 Agent 工具授予。旧版仅宿主保存的自动权限须人工续授，不自动迁移为新签名权限。

回执、签名 nonce、授权使用和计划累计费用在同一 SQLite 事务中提交。计划的钱包、网络、范围和预算不能原地改写；重启或换授权不会重置计划预算。已签名后停止的 nonce 不自动释放，普通交易可由用户明确确认原交易哈希后使用同一 nonce；GUI / WebUI / TUI 都有对应警告和不同按钮文案。现有自动计划不能静默复用它。这不代表完整的待确认交易加速 / 替换 API 或可选自动替换策略已实现。前端确认摘要也改为覆盖交易 nonce / gas / 费用 / 期限和替换引用，费用显示使用整数格式化。

真实签名进程已验证缺少审批、内容变化、换解锁会话、拒绝后重放、错误链 / 费用 / 过期、撤权代次、明确 nonce 替换以及计划预算跨重启 / 换授权 / 改范围。源码隔离链已验证停止后的人工 nonce 恢复和原生调度流程；共享审批组件另有深浅色布局、完整哈希引用转发与截图验收。该控制面仍信任用户界面及共享后台，不宣称能够对抗同一 OS 用户的任意代码。

进一步的当前内部协议为 4、原生授权版本为 2：增加单笔 ETH、累计签名 ETH、累计费用、签名笔数、最外层目标地址 / 方法白名单和调用数据开关。授权计数与回执共事务保存，跨进程重启保留；同一签名重放不重复计数，替换签名会占用预算。当前授权的预算共用于其网络和计划，用户明确新授权限后可开始新的授权预算，但已有计划的独立费用预算不因此重置。没有可信历史累计计数的旧授权在迁移时撤销，不凭空创建零用量。

GUI / WebUI 与 TUI 共用授权字段定义、三语标签和后端标准化。设置增加默认关闭的自动 nonce 替换选项，用户须在范围复核后完成原有二次确认；开启后仍必须绑定当前原签名哈希并服从预算、停止锁与所属计划权限。只实现已知未广播签名的 nonce 复用，不冒充完整的待确认交易加速 API。ETH 限额只约束交易 value，不能约束代币 / 合约内部支出；白名单也只检查最外层调用。前端明确显示该范围，配置变化在二次确认阶段冻结。

## 原生执行方向

新增 Base 定时拆单发件箱基础层：固定模板和不可变计划绑定钱包 / 链、输入代币最小单位总额、段数、间隔、滑点、池费、配置摘要及授权标识。计划、领取、回报和金额预算与现有原生账本共用 WAL。分配余数使用整数；一次只保留一段未结算命令，同一钱包 / 链存在运行或待核实命令时不能另启计划。授权标识只用于绑定元数据，原生进程仍没有签名、网络或钱包权限。

当前模板是等待上一段最终确认后再计时间隔的串行拆单原型，不宣称已实现完整固定时间窗 TWAP / VWAP。单调时钟驱动，无逐笔 LLM 调用；过期时不会集中补发。领取使用持久标识，已领取后崩溃或停止保留待核实状态，不能当作未发送再领；只有未领取的计划可明确取消。已入块和 safe 回报不会冒充最终确认。全局暂停和后台关闭持久暂停计划，单独启用 PAPER 不会恢复它。

已通过 52 项 Rust 测试和零警告 clippy；当前 Windows x64 受管资源的 20 项真实进程测试通过，包含定时、精度边界、停止 / 重启、领取冲突、证据保护、原生全局暂停、实盘专用暂停及离线回放隔离。源码和打包 Node 后台均验证私有发件箱恢复；通用前端请求和 Agent 工具不能上报成交。完整检查为 714 项通过、3 项跳过及 388 项兼容测试通过。

发件箱现已连接共享后台的 WalletService 和 Agent 工具 quant_live_execution，提供项目内创建、启动、停止、分页历史及只读对账。每段固定启动授权、配置摘要和逻辑操作 ID；钱包队列在准备、签名返回和广播前检查所属计划与当前权限。停止、全局暂停、配置变化、撤权或延迟启动回调不能恢复旧派发权限。模型不能伪造成交、授予自动实盘权限或单独批准计划内交易；计划启动仍须由用户先在钱包设置阅读警告并确认自动实盘权限。

批准代币和兑换共用计划的累计预估费用预算，钱包记录跨重启保存该作用域；预算包含失败 / 未发送尝试的保守估计，不冒充 Base L1 费用的链上硬上限。批准已完成而兑换未发送时使用中止回报，保留已有链上授权和费用记录。未知广播结果只对账；钱包锁定或用户撤权不阻止只读恢复。

源码和打包 Node 后台均已用原生调度器、真实加密签名器和隔离 Anvil 验证两段代币转移、精确批准、最终确认、签名期间停止 / 撤权 / 全局暂停 / 配置变更、预估费用不足、隐藏确认和锁定钱包重启对账。合约是源码和字节码均校验的固定价格测试夹具，不是真实 Uniswap 部署或公网资金验收。CI 接入同一验证，当前本地只验证 Windows x64。GUI / WebUI 共用实盘计划组件，TUI 使用同一后台和三语标签；支持默认暂停创建、独立启动 / 停止、最终确认进度、费用、分页记录与对账。隔离 Electron 检查创建不授权、无交易派发、刷新不打断输入及关闭不改变计划状态；TUI 测试覆盖授权显示、作用域、18 位金额及丢失确认后保留同一操作 ID。其他执行协议、硬性组合风控和完整固定时间窗 TWAP / VWAP 仍未实现。

钱包实盘广播另补了授权竞态修复：钱包解锁会话和自动执行授权分别保留代次；签名前、签名返回后、写入交易哈希时及实际调用广播 RPC 前再次检查。锁定立即清除主机授权；旧解锁回调不能复活已锁定的钱包，也不能清掉较新的有效解锁。撤权先写独立的持久暂停记录，再排队更新主钱包记录，避免普通请求卡住或中途重启恢复旧自动权限；暂停记录损坏时关闭钱包能力。

发送前中断记录为确定未广播；广播 RPC 已调用后的中断保留交易哈希和结果待核实状态，不自动重发。GUI / WebUI / TUI 增加对应的三语说明；Agent 提示词明确区分撤权和链上撤销，不得靠换钱包或操作 ID 绕过撤权。已用真实加密签名进程和本地 Anvil 分别验证发送前撤权无转账、节点已接受后撤权仍只有一笔转账且可对账，并覆盖跨重启恢复；这不代表独立连续策略实盘桥已经完成。

此前钱包广播改动的验证：钱包 / Base 兑换 / 实际主机 HTTP 取消共 31 项测试通过；源码与打包 Node 后台均通过真实本地链验证；当时完整检查通过 694 项现代测试、3 项跳过及 388 项兼容测试。当前累计验证结果见上文，未使用公网实盘资金，未提交或发布。

此前新增原生账户紧急停止：一次账本事件停止共享账户的 PAPER / SHADOW 部署、撤销其剩余订单、释放预留并保留已发生成交与费用；持久停止锁阻止重新启用或新建运行。前端人工确认只能解除所见的当前锁，解除仍保持暂停；Agent 只有停止动作。已通过部分成交、跨项目共享 / 其他账户隔离、存储失败、跨重启、陈旧重试 / 确认、普通请求延迟下停止优先，以及深浅色 GUI 交互和截图验收。当前原生资源的 20 项真实进程集成通过。仿真控制与新增的实盘全局停止各自独立；二者均不冒充尚未接入的交易所撤单。

实盘全局停止已单独验证：签名器关闭、未发送操作阻断、停止记录校验与保存失败、繁忙队列、迟到解锁 / 授权 / 签名、恢复旧钱包状态、暂停回调先于解除、失败重试及旧确认防重放。GUI / WebUI 共用停止与二次确认界面，TUI 使用同一服务与三语标签；真实 Electron 验证停止后锁定 / 撤权、人工二次确认及解除不重启计划，并保存深浅色截图。原生实盘专用暂停保持 PAPER 启用状态；源码和重新构建的 Node 后台均通过加密签名器及隔离链验证。Node 打包测试应先执行 `npm run build:node-core`，避免验证到旧产物。

原生基础模块用 Rust，控制界面和 Agent 仍使用现有共享后台。密钥和实盘授权继续归钱包服务管理；原生内核不能凭自己的账本绕过钱包授权。

行情网络接入先由主机后台处理，保留现有代理和隐私设置。不得由原生进程悄悄开启绕过代理的连接。新增连续执行须使用明确的策略状态、资金预留、持久命令 / 回报和对账流程；不能由 LLM 每个 tick 决策，也不能用常驻 while 循环代替订单状态机。

参考成熟事件驱动架构的分层和恢复模式，但不宣称已集成任何第三方交易引擎。原生库的测试通过不替代产品集成和实盘协议验收。
