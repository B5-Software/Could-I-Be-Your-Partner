# 技术栈与代码整理记录

本轮改造日期：2026-09-30。应用继续使用 Electron，现有界面与主要功能保持兼容；
改造重点是拆分职责、建立可靠构建与检查流程，并修复实际发现的数据、安全和并发问题。

## 架构与构建

- 从原先约 9,471 行的主进程入口中拆出 18 个功能模块，入口缩减至约 4,400 行。
  `src/main/ipc/` 注册各功能通道，`services/` 管理预算与历史，`settings/` 管理默认值与合并。
  模块显式接收依赖，通过 getter 获取变化后的设置与窗口，避免旧引用与初始化顺序问题。
- `src/main/core/` 集中提供私有 IPC 路由、窗口信任校验、原子 JSON 存储和数据 ID 校验。
  路由不再修改 Electron 全局 `ipcMain.handle`，保留虚拟机工具路由能力。
- 新核心逻辑使用严格 TypeScript；`src/shared/pricing.ts` 在主进程和 UI 中共用，
  消除两套费用算法在价格、时区与缓存计费上的差异。
- esbuild 构建 ESM 渲染入口、共享 CommonJS 产物、Linux guest 工具包和 15 个沙箱预加载脚本。
  source map 能追溯到 171 个旧 UI 文件和独立 TypeScript 源码；构建不会改写模板中的空白。
- 旧 UI 仍保留一个共享兼容作用域，顺序由 `src/renderer/legacy-parts.json` 声明。
  构建会拒绝遗漏、重复与缺失文件。此轮未将全部 UI 改写为 TypeScript 或新框架。

## 修复的问题

- LLM 响应中的未声明全局变量会使并发请求相互影响；现改为请求内局部变量并验证并发隔离。
- 远程附件消息重复使用 `type` 字段，MIME 类型覆盖协议消息类型；现统一使用 `mimeType`。
- 保存配置或历史时，失败后的直接覆盖可能损坏原文件；现采用独占临时文件、刷新与原子替换，
  替换失败保留上一次有效数据。
- 部分配置更新会清空同层设置或默认值；现使用深层合并，保留兄弟字段，拒绝原型污染键。
- 历史、技能与会话 ID 可拼接到存储路径；现校验 ID，阻止路径穿越。
- IPC 校验调用者必须是已登记的本地顶层页面；应用预加载窗口启用沙箱和上下文隔离，
  阻止外部导航、弹窗和 webview 继承权限。
- 预加载事件监听集中管理，取消订阅具备独立身份与幂等性，窗口卸载时释放监听。
- 修复 macOS 权限检查缺失导入、语音错误事件被重复分支吞掉、下载流程中 finally 覆盖返回值、
  异步 Promise executor 和 PDF 解析资源释放等问题。
- 修复工作区根目录在初始化前被引用，以及重复翻译键和重复导出。
- 文档解析适配 Office parser 8 的异步 `ast.to('text')` API，知识库与 Word 工具共用适配层，
  验证真实 PPTX、RTF 与 ODT 导入；邮件编码与解析通过本地 MIME 往返验证。
- 预算周期统一按预算时区的日历日期计算，修复跨午夜与夏令时边界下周起点、滚动周期偏差。
- 默认测试不再自动读取真实模型配置并调用付费服务；真实模型测试需要显式开启。

## 工具链与依赖

开发环境统一为 Node.js >= 24.13.0、npm >= 11，Electron 升级到 43.7.6，
引入 TypeScript、esbuild、ESLint、Prettier、原生 Node.js 行为测试与 CI 检查。
依赖与锁文件已同步更新，ONNX Runtime、文档解析、邮件、网络和压缩库均进行了兼容性检查。

依赖审计从 18 项高危、10 项中危降至 **0 项高危、0 项严重、7 项中危**。
剩余问题来自桌面控制依赖 `@nut-tree-fork/nut-js` 的 Jimp / file-type 链，
当前没有兼容的自动修复方案。后续应升级或替换这条依赖链；不能将此结果解释为没有任何漏洞。

## 日常维护命令

| 命令 | 用途 |
| --- | --- |
| `npm start` | 构建后启动应用 |
| `npm run check` | 正确性、格式、类型、构建与离线回归检查 |
| `npm run format` | 格式化新增模块与测试，避免无关旧源码的大量改动 |
| `npm run test:desktop` | 在临时配置目录中验证完整应用启动与隔离 |
| `npm run test:ocr` | 验证本地 Tesseract / PaddleOCR 引擎 |
| `npm run test:live` | 显式使用已配置的真实模型，可能产生费用 |
| `npm audit --audit-level=high` | 检查是否出现新的高危依赖问题 |

新增主进程功能应使用独立注册模块与显式依赖；新增可独立的 UI 逻辑应使用导入与导出。
修改旧 UI 文件时编辑 `app-parts/` 原文件，增删文件时同时更新清单。
`app.js`、`src/preload/generated/` 和 `src/shared/generated/` 是生成产物，不提交、不手改。

## 打包与验证边界

打包使用运行文件白名单，不再临时移走 `.git` 或开发目录。
修复了平台级负向 `files` 规则意外引入整仓库的问题：
ONNX 的平台排除规则现在加入同一个根文件集合，并在切换目标平台时替换。
打包后检查关键运行文件、许可证和开发资源边界，缺失或混入禁用目录会使构建失败。

本地 Windows 验证包括 52 项行为测试、388 项既有离线回归、完整桌面启动与两套 OCR 引擎，
以及真实的 Windows 目录打包。目录打包检查关闭了签名与原生模块重编译；
不代表已完成签名安装包或 macOS / Linux 的原生构建验证。
CI 配置在 Windows 与 Linux、Node.js 24 与 26 上执行检查，实际远端结果需由 CI 运行确认。

VM 终端现在直接进入已同步的实际工作目录；App 个性化实时同步到 OS 桌面。
桌面源码仅在独立 OS 仓库中，随镜像发布。修复了每次启动重建实例盘的问题：
同一镜像重启复用用户盘，不匹配的用户盘保持原状，新镜像使用独立实例盘，旧数据保留。
真实 QEMU 验证覆盖两次启动、SSH 密钥轮换、文件保留和镜像不匹配时的磁盘保护。
独立 OS 仓库已提交并发布 `0.3.1`，六种镜像的 CI 全部通过；
本机正式 Full 镜像验证了 App 连接 Wayland 桌面及无需重启的深浅色、强调色、背景色同步。
工具处理和文件位置的修复、真实 VM 测试及应用管理数据边界见 [VM 工具隔离](vm-tool-isolation.md)。

主进程入口仍承载窗口与部分应用编排，旧 UI 仍共享兼容作用域。
下一步可按功能逐个迁移这些边界，优先抽离会话、窗口生命周期与 UI 状态，
每次迁移保持行为测试和启动检查通过。
