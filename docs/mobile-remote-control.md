# 共享后台与原生远程客户端

GUI、TUI、WebUI 使用同一个后台进程。Agent、自动化、插件、设置和 VM 均由后台持有；关闭一个前端不会复制任务或停止其他前端的会话。后台为请求分配幂等 ID，事件带递增序号，断线后按游标重放；游标过期时重新获取快照。

WebUI 直接复用 GUI 的 HTML、CSS 和渲染代码，不再同步 GUI 的 DOM。`cibyp-webui`（或别名的 `-webui`）在后台启动服务；设置中可配置随任一前端启动。必须先设置访问密码，默认仅监听 `127.0.0.1`。Remote 模式连接同一后台，Code-OSS Web 工作台也由后台代理。

## Tor 远程连接

设置 → WebUI 中配置密码和可选的二次认证，再启动 Tor。桌面内置经过官方 SHA-256 校验的 Tor Expert Bundle，建立 v3 onion 服务到本地 WebUI；无需打开路由器端口。可填写 obfs4、snowflake、webtunnel、meek 网桥，也可点击“使用内置 meek 网桥”。内置 meek 参数取自 Tor Expert Bundle 15.0.24 的 `pt_config.json`；支持自定义 `url` / `front` / `targets`，将 `meek` 自动转为运行时要求的 `meek_lite`，指纹可选。修改配置后重新连接 Tor。连接过程中显示下载、初始化、引导进度及错误；停止 WebUI 同时停止 Tor。

隐藏地址不能代替身份认证。所有 RPC 均要求认证与请求 ID，WebSocket 会话过期后需要重新登录。不要公开访问密码。网桥是否有效取决于实际网络与网桥可用性，不能保证所有网络都可连接。没有配置网桥时使用 Tor 的默认连接；不会在 Tor 失败时回退到公网明文直连。

## Android / Wear OS

原生移动客户端在独立仓库开发，桌面安装器不包含手机 APK。Android 使用 Kotlin、Jetpack Compose Material Design 3、系统深浅色、预测性返回及桌面小组件；客户端是控制面，文件、工具、模型请求仍在原电脑执行。

手机内置 Tor 与可插拔传输，可选网桥；支持多个电脑、会话、任务停止、审批、共享待办与用量。登录后的访问令牌使用 Android Keystore 加密保存，访问密码不持久化。

Wear OS 通过手机的 Data Layer 转发请求，没有相机或扫码要求。需要系统配对、两端安装同一签名的应用，并在手机中明确允许该手表。手表收到设备列表，不会收到访问令牌或模型密钥。手机连接服务停止后，手表不能继续控制电脑。

`/update` 在各前端调用同一个桌面更新服务。安装前需手动确认；任务运行中拒绝重启。手机与手表 APK 的升级由各自安装渠道管理。

移动端的构建与实机连接结果以独立仓库的 CI 和发布说明为准；桌面测试不能代替手机、手表或受限网络的实机验证。

移动端 0.1.0-alpha.2 起，手机与手表同步所选电脑的强调色、背景色和解析后的深浅色；切换目标时不会继续沿用上一台电脑的主题。设置变化推送到已连接手机，再通过 Data Layer 同步给手表。手机不逐 token 拉取推理，而是在完成或状态变化后合并刷新；手表仅刷新当前页，前台聊天在请求结束后等待 10 秒，其余页等待 30 秒，离开前台停止轮询。

推理摘要、加密保留开关及验证范围见 [推理与验证说明](reasoning-and-verification.md)。
