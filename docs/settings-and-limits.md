# 设置与限额

设置共有 36 个分类。首页显示当前模型、Token 分配、累计限额、执行位置、主题及 System One 状态。普通字段自动保存，连接、安装、检测等操作仍使用对应按钮。

更新页会识别安装来源。npm 启动器下载并校验新版运行时，下次启动启用；直接安装的 Release 下载并校验对应平台的官方安装包，再由用户确认安装。默认自动检查、不自动下载，可开启后台下载。GUI、TUI、WebUI 和移动端共用下载状态，同一版本只下载一次；存在运行中的任务时不会自动安装。源码开发模式只检查更新。

模型与连接页首先显示模型池。ChatGPT 账号下的模型选择器用于将当前账号的可用模型加入池中，并设为新会话默认值；已有会话保持原模型，可用 `/model` 手动切换。

ChatGPT 的直接订阅授权使用主机的 Responses HTTP/SSE 请求。它不保证提供旧 Codex 账号标识，也没有公开的额度读取接口；此时额度区域提供用量管理说明，模型仍可使用。用量页与登录页打开主机浏览器。缺少 Codex 账号标识时不会调用旧 Codex 额度 RPC，也不会将缺少标识报告为登录故障；已有有效账号标识的连接保留兼容的额度查询。参考 [OpenAI 用量跟踪说明](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions#tracking-usage)。

LLM、外置视觉、生图、System One 的网络请求由主机后台执行，与工作区运行位置分开。VM 模式下工具、终端和生成文件仍使用 VM 工作区。同步扫描遇到占用文件会短暂重试，持续占用的文件及目录保留基线、禁止传播删除并等待后续同步；其他文件可以继续导入。

## 限额入口

| 控制范围           | 设置位置                   | 保存字段                                              | 生效方式                                                               |
| ------------------ | -------------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------- |
| 单次请求总容量     | Token 与上下文／模型池条目 | `llm.maxContextLength`／`llm.pool[].contextLength`    | 会话使用自己所选模型的容量；修改默认模型容量只更新当前默认池条目       |
| 单次生成输出       | Token 与上下文             | `llm.maxResponseTokens`                               | 主请求、摘要、标题等辅助请求和外置视觉共同遵守；辅助请求可使用更低上限 |
| 工具定义占用       | Token 与上下文             | `toolExposure.mode/budgetTokens`                      | 按需加载时限制定义占用；自动工具选择预加载候选，支持 System One 和本地回退    |
| 历史压缩           | Token 与上下文 → 高级      | `contextCompaction.*`                                 | 阈值、保留比例、摘要输出及重试次数；摘要输出同时受单次输出上限约束     |
| 每日累计 Token     | 消费与用量上限             | `budget.dailyTokenLimit`                              | 文本、流式文本、摘要和外置视觉在统一入口检查及记账；达到后停止新请求   |
| 每日生图张数       | 消费与用量上限             | `imageGen.dailyMaxImages`                             | 生图服务按张数检查                                                     |
| 每日 System One 调用次数  | 消费与用量上限             | `decision.dailyMaxCalls`                              | 达到后使用原有本地回退逻辑；与 Token 分开计量                          |
| 日／周／月美元预算 | 消费与用量上限             | `budget.dailyLimitUSD/weeklyLimitUSD/monthlyLimitUSD` | 三个周期同时检查；达到任何美元预算时按“提醒”或“停止”处理               |
| 单个目标任务预算   | 任务目标界面               | 目标记录中的预算                                      | 保留任务范围，设置概览说明其与累计限额的区别                           |

累计限额设为 0 表示不限。Token、图片和 System One 使用相同的预算时区日期；周和月支持自然周期、滚动周期。

## 实际分配

前端和请求构造共用 `src/shared/token-policy.js`。单次输出最多使用配置值，为输入保留至少 `min(4096, 模型容量 / 2)` tokens；工具定义上限还会按输入空间的 20% 收敛，保留发现工具所需的最低空间。页面显示当前会话容量、输出预留、输入空间和实际工具上限，配置值保持不变。

输出、工具占用和压缩策略分别调整。完整加载工具模式显示“完整加载”，并禁用不生效的工具上限输入。

旧式 Anthropic thinking 的预算包含在输出上限内，通常最多使用输出空间的 75%，为答案保留空间；不会再自动提高 `max_tokens`。[Anthropic extended thinking 文档](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)说明了两者的约束。

## 费用与计数

美元消费按本地模型价格表估算。没有价格的模型记录 Token，但金额为 0；配置外置视觉时也需要添加其模型价格。System One 按调用次数统计，生图按张数统计，不加入 LLM 的 Token／价格表费用。

API 返回用量时采用其结果；缺少用量时估算文本 Token，外置视觉无法在这种情况下精确计入图片输入。限额在发送前检查，已发出的请求可能结束后超过限额。费用统计不代表供应商账单。

“清零今日用量计数”收进高级选项，只重置 Token 和图片张数；费用历史和美元预算消费保留。System One 调用计数保持其独立服务记录。

## 配置迁移与保存

- `llm.dailyMaxTokens` 自动迁移到 `budget.dailyTokenLimit`。
- `monthlyCapUsd`、`overAction` 迁移到对应的规范字段。
- 原“自动换模型”预算选项在后端本来就会停止请求；迁移为 `stop`，移除无效模型字段和界面入口。
- 旧限额迁移到规范字段，个性化保持原配置；迁移可重复执行。
- 设置页面通过 `SettingsClient` 对读取快照求差异，只提交改动字段并串行写入，防止不同设置互相覆盖。价格表作为完整字典替换，使删除真正生效。
- 保留原有主进程去抖持久化和退出时刷新；写盘采用已有原子 JSON 存储。

## 设置页检查与改进

所有分类补充用途及生效提示，统一控件标签与键盘切换。搜索覆盖高级选项和分类关键词，结果可跳转、展开并聚焦；隐藏的条件字段不参与搜索，搜索不读取 API Key／密码输入值。

价格表、峰谷定价、压缩细节及直接编辑连接收进高级折叠。新增保存状态和数值校验，预算自动保存使用页内状态提示。导航颜色跟随强调色，支持深浅色及窄窗口。每个分类拥有独立垂直滚动区域，切换分类或离开后重新打开设置时回到顶部；设置目录单独滚动。大卡片间距为 20px，模型池、资源、MCP、插件和授权列表间距为 12px。

修复周预算／时区未保存、零次压缩重试和零倍峰谷价格无法保存、重复绑定事件、费用预警遮蔽其他周期超限、视觉／摘要绕过累计限额、全局容量覆盖会话模型、一级页面多余的关闭按钮，以及邮箱零次重发和重发数量少一次的问题。

预算计数管理卡片的结束标签曾缺失，导致主题至安全分类嵌进预算分类并被隐藏。现已恢复全部分类为同级面板，并增加实际可见性、卡片间距和滚动区域检查。特殊 WebContents 没有 preload 首选项时会跳过应用窗口保护初始化，应用 preload 的导航、弹窗和 webview 限制继续有效。

## 验证

- `npm run check`：lint、格式、TypeScript、单元测试及原有回归。
- `npm run test:desktop`：隔离配置运行完整 Electron App，遍历全部 36 类设置，检查实际可见性、独立滚动与切换归零、44 处卡片间距、控件标签、搜索、有效数值、并发保存、System One 限额、周预算、时区、零次重试、零倍率及价格删除。
- 单元测试验证迁移、模型容量分配、输出／thinking 限制、限额优先级、四种 LLM 入口阻断、外置视觉记账、保存失败重试、System One 日期和邮箱重发数量；测试不会调用供应商或发送邮件。
- `CIBYP_UI_PREVIEW_DIR` 可输出深浅色的概览、Token、预算、主题、安全、待办侧栏以及窄窗口预览。

macOS 的原生 Computer Use 测试在 Windows 跳过；本轮不涉及其原生实现。
