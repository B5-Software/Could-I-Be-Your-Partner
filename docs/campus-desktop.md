# Campus 桌面与 App 个性化同步

App 的「个性化」是连接状态下的统一外观来源。深浅色、强调色和背景色同时应用于 App 与 VM 桌面；跟随系统模式使用宿主的实际深浅色。VM 没启动时不为换色启动 VM，下次 VM 就绪或打开桌面时应用最新设置。

## 使用与更新

新版桌面只从独立 `cibyp-vm-os` 仓库构建进 OS 镜像。发布版本为 `0.3.1`，推送 `vm-os-v0.3.1` 标签触发现有镜像 CI，产物发布到 `vm-os-latest`。App 通过既有 VM 资源下载入口安装新镜像，不携带桌面源码或桌面更新包。同一镜像重启复用用户盘；新镜像使用独立用户盘，旧版本磁盘保留。共享工作区继续同步，独立工作区可从旧版本导出后导入。

桌面使用 Sway、GTK 4、PyGObject、Cairo 和 VTE。校园插画、统一矢量图标、底部任务栏、开始菜单、工作区、窗口最小化/恢复/贴靠、桌面与应用右键菜单均为真实原生界面。文件管理器、编辑器、终端、计算器、图片查看器、设置与关于窗口已重写。

深浅色、强调色与背景色通过既有 SSH 通道同步到 `~/.config/cibyp/desktop.json`。只传公开外观字段；写入使用进程锁、临时文件、同步写盘和原子替换。桌面和内置应用监控配置目录，重绘现有窗口，无需重启应用。背景色派生规则与 App 一致，校园插画也使用同一背景基色。

快速连续换色的写入串行执行，并合并 VM 尚未处理的中间状态。重复配置不重复写入；VM 重启会重新应用。同步保留 VM 的壁纸、固定应用、隐藏文件等偏好。连接 App 后，VM 外观页显示跟随状态，并由 App 控制这三个外观字段；独立使用 OS 时，VM 设置页仍能自行修改配色。

Chromium 继续提供原生 Wayland 浏览器和现有 CDP 自动化能力。网页内容及第三方应用的内部配色由各自的主题支持决定。

## 工作目录修复

App 终端创建前先同步当前会话或 Code 项目的实际目录，包括空目录与额外工作区根。随后校验 VM 目录并直接在 SSH PTY 启动前进入目标目录。同步失败或目录不可用时明确报错，不再静默落到 `/workspace`。特殊字符按 shell 参数转义，分包的中文终端输出使用连续 UTF-8 解码。

## 代码位置

- `src/main/vm/vm-theme.js`：主题映射、队列与原子更新。
- `src/main/vm/vm-graphics.js`：独立会话目录、Wayland/VNC 启动与进程生命周期。
- `src/main/vm/vm-service.js`：VM 就绪时恢复主题与工作区；终端目录准备。

桌面源代码位于相邻 `cibyp-vm-os` 仓库的 `recipes/overlay/desktop`，由该仓库的镜像配方和 CI 安装到 `/usr/local/lib/cibyp-desktop`。App 只保留主题同步、终端目录修复与图形连接生命周期。

## 验证与边界

`npm run check` 检查正确性、格式、类型、构建、单元行为及既有离线回归。`tests/integration/desktop-smoke.cjs` 用临时配置验证完整 Electron 启动。

OS 仓库的 `tests/desktop_smoke.py` 使用真实 Wayland/RFB 鼠标和键盘，验证文件操作、终端实际目录、编辑器保存/撤销、图片/计算器、任务栏和菜单，并调用 App 的生产主题通道检查六个运行中窗口的实际像素颜色与窗口未重启。

`0.3.1` 的六种镜像（amd64 / arm64 × base / desktop / full）均通过镜像构建和 QEMU 启动检查，已发布到 [正式镜像入口](https://github.com/B5-Software/cibyp-vm-os/releases/tag/vm-os-latest)。本机 Full / amd64 镜像的系统盘、内核和 initrd 均与正式清单的校验和一致。

`tests/integration/vm-image-native.cjs` 使用本机 QEMU 和正式 `0.3.1` 镜像，在独立临时用户盘中验证两次启动、版本信息、SSH 密钥轮换、文件保留和镜像不匹配保护，并通过 App 的生产连接代码启动 Wayland 桌面。深浅色、强调色和背景色切换均通过配置及真实截图验证，桌面会话保持运行。测试不使用或重置现有用户盘。
