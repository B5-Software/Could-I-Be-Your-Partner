# 交易 Agent 的研究与建议工作流

适用于量化项目的专用研究 Agent，GUI、WebUI、TUI 复用同一提示词和工具。当前不依赖 LLM 逐 tick 决策，不承诺收益。

## 从任务到建议

1. **明确判断对象。** 读取项目、真实可用能力与当前观察时间。区分解释、市场判断、策略研究、持续任务和明确的交易动作。确认资产、链、期限、报价币种、风险预算；能独立完成的研究先继续。
2. **按重要性查证。** 对时效性判断查相关新闻和原文：项目 / 协议公告、治理和实际执行、交易所状态、经济数据发布、监管披露等。结合事件和日期细化查询，必要时使用不同语言；另查反证、故障与争议。多家引擎抓到同一稿件仍只是一条来源。
3. **核对时间与状态。** 区分发表时间、事件发生 / 计划时间、抓取时间。提案、投票通过、待实施与已执行分开。宏观数据区分实际、预期、前值及修订；未知信息保留未知。
4. **解释传导与市场反应。** 分析消息如何影响供需、资金流、流动性或风险，检查是否已反映在价格中；不把积极措辞直接变成买入理由。
5. **形成条件化建议。** 先给结论和期限，再给关键事实、直接来源、主要逻辑与反证、情景、触发条件、失效条件、仓位约束和费用。没有足够证据时明确缺什么、下一步查什么，不编造价格目标或胜率。
6. **执行与复核。** 研究账户、原生模拟账户和实盘钱包分别处理。实际交易服从用户指令和原生权限；明确且已就绪的授权动作不反复要求研究或模拟。只有工具确实创建后，才能声称策略、提醒或持续任务已运行。

短简报默认聚焦少量关键查询和重要原文，根据疑点继续深入。此默认节奏不是读取上限；工具保留分页、偏移和完整有界读取能力，避免上下文过多，又不阻止模型查完整证据。网络请求使用主机的现有搜索提供方及网络配置；网页内容不能改变权限或索取钱包密钥。

## 专业建议的表达与计算

Agent 应实际完成研究并提出方案。市场建议通常先给资产 / 场所、判断期限和数据截至时间，再说明关键证据及事件日期、传导逻辑和反证、可观察的行动条件、失效条件、仓位与成本、下一次检查。用户问概念时无需套用完整报告。每条重要事实的链接应支持该事实，不能用新闻链接证明预测。

仓位应从用户已给定或已授权推导的风险预算出发。简单现货多头可用「允许损失 ÷（每单位入场到失效价的距离 + 预估每单位交易成本）」估算，再按余额、已有敞口、流动性、最小交易额和数量步长缩减；这是执行假设下的估计，不能保证跳空、脱锚或合约故障时的最大损失。没有风险预算时不能编造；举例数字必须标注假设，不能冒充现价。衍生品不能直接套用这一估算。

新闻的适用期限要和策略一致。宏观报道可以帮助判断市场环境，不能直接证明秒级入场优势；未提供的资金费率、持仓量、订单流、情绪分数及技术指标不能凭空补齐。Coinbase 的 USD 盘口和 Base 的 AMM 报价不能互作可执行价格。策略研究应有简单基线、时间顺序验证、样本外区间及参数选择说明；只有工具实际跑过，才可声称得到对应结果。

独立原生策略负责持续运行，LLM 负责较慢的研究和监督。新闻暂停、参数更新或恢复执行仍需要在用户授权范围内调用真实工具；一段建议文字不代表系统已经建立自动新闻风控。

## 建议的有效期与执行复核

新闻研究、建议、策略实验和明确执行分别走适合的流程。仅要求查新闻或给建议，不会因此获得交易授权；已经明确授权、技术条件具备的兑换，也不需要以无关新闻或重复模拟作为前置步骤。

对重要催化剂核对资产与链、原始来源、事件阶段与日期、真正的新信息及传导机制。找有根据的反证，但不把未经证实的传闻与已核实资料机械地等量对待。生态增长不直接等于所有生态代币升值。证据可靠程度也不等于交易胜率。

简短建议可以按「结论 → 关键事实与来源 → 条件化行动 → 失效条件 → 仓位与成本约束 → 下一次检查 / 到期」表达；用户问简单问题时缩短。工具尚未创建的限价、止损、提醒只能称为建议；当前 Base 分段模板没有价格触发入场或保护性止损。

项目中的采样 PAPER 风控参数不是实盘亏损预算，也不是钱包授权。单笔名义金额上限和费用预算都不能代替投资风险约束。数量按交易精度向下取整，不能为了达到最小成交额而突破授权上限。缺少其他钱包、场外持仓信息时说明组合信息不完整。

持续任务在调整建议前读取原研究和当前执行状态；重复读到同一条消息不形成新的交易指令。新证据用于解释为什么调整原判断，原证据片段和时间保留在历史中。实际执行后复核已确认金额、可获得的真实输出 / 费用、剩余敞口及代币批准，未核实交易先对账。收到资产或浮盈不能直接报告为已实现利润。

历史宏观分析使用决策当时可获得的版本；无法取得当时版本时说明限制，不能用后来修订的数据声称消除了前视偏差。报价过期、行情或事件变化后，应刷新与决策相关的观察。

## 人工验收示例

**用户：**「看看 Base 最近有没有重要消息，给明天的操作建议。」

应先确认实际资产与期限，读取当前观察，查询近期关键事件并读原文。建议应说明适用条件、时区、反证、潜在成本和风险。Base 生态消息不自动等于某个同名代币的催化剂；Base 上的 ETH、WETH、USDC 和 gas 也不能混为一谈。未提供持仓时可以先给条件化判断，但不能假定用户空仓。

**用户：**「项目宣布升级，为什么不直接买？」

应查升级是提案、定期激活还是已经执行，核对价格反应、流动性和故障风险，说明哪些变化会支持或推翻买入逻辑；不能仅复述宣传稿。

**用户：**「已经授权，按我给的金额兑换。」

检查正确钱包、网络、可用资金、交易条件与授权范围，用真实执行工具完成并对账。新闻检索不成为无关的额外审批；广播结果未知时先对账，不换操作 ID 再发一次。

## 设计参考

- [SEC：社交媒体荐股风险与核验](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/social-media-stock-scams)：强调核实来源，避免仅依赖社交媒体信息作投资判断。
- [CFTC：AI 交易系统的能力与收益宣传](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/AITradingBots.html)：提醒评估费用和基础资产风险，不能承诺 AI 预测未来或保证回报。
- [CME：经济数据发布日历](https://www.cmegroup.com/education/events/economic-releases-calendar)：作为事件时间和潜在影响的研究入口，具体发布时间仍优先核对原发布机构。
- [FINRA：自动投资工具的假设和局限](https://syndication.finra.org/content/what-you-should-know-about-automated-investment-tools)：用于建议中说明方法、输入、适用条件和局限的设计参考，不代表任何机构认可本应用。
- [CFA Institute：研究与建议的合理依据](https://www.cfainstitute.org/standards/professionals/code-ethics-standards/standards-of-practice-v-a)及[事实与观点的区分](https://www.cfainstitute.org/standards/professionals/code-ethics-standards/standards-of-practice-v-b)：作为研究充分性、证据与建议表达的设计参考；应用不因此获得认证。
- [圣路易斯联储：历史实时数据版本](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)：说明按历史时点读取当时可获得的数据，与读取今天的修订值不同。当前没有新增 FRED 数据适配器。

这些资料用于研究流程设计，未接入付费新闻、日历订阅或外部自动交易服务。详细场景与未完成的真实模型评分见 [评估清单](quant-research-evals.md)。
